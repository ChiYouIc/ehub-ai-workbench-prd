# 02 前端工程规范 — 全工程前端通用约定

> 范围：ehub-web 全部模块前端 ｜ 状态：**r1（2026-08-24）**
>
> 本文是**前端工程约定的单一事实源**：API client、响应解包、错误处理、SSE 消费、状态管理。与 `designs/ui-baseline.md`（视觉/交互基线）互补：基线管「长什么样、怎么交互」，本文管「工程上怎么组织与消费后端契约」。构建与目录随 ehub-web 现有工程，不在本文自立。后端出参形态的单一事实源在 `requirements/web/01-响应包装.md`、`requirements/web/02-错误与异常.md`——本文只定义前端侧消费方式，不重复定义契约。

## 1. 技术栈基线

- Vue 3 + Element Plus（与 ui-baseline §1 一致）+ Vue Router + Pinia。
- HTTP client：axios（单实例封装，见 §2）。

## 2. API client 与响应解包

后端统一包装（`requirements/web/01-响应包装.md`）：成功 `{code:0,data}` / 分页 `{code:0,total,data}` / 失败 `{code,message,time}`，**HTTP 状态恒 200（业务异常）**——因此分支依据是 `body.code`，不是 HTTP status。

**统一解包拦截器**（axios response interceptor，全工程唯一实现）：

```
成功：body.code === 0        → 返回 data（或 {total,data}，分页接口）
失败：body.code !== 0        → 统一错误处理（§3）后 reject
HTTP 层错误（网络/超时）      → 同 §3 兜底路径
```

- 业务代码拿到的 Promise 永远是**已解包的 data**，不重复判 `code`。
- 分页接口约定：拦截器识别 `total` 字段原样返回 `{total, data}`，调用侧不得假设纯数组。
- **SSE 接口不走 axios**（`@SkipWrapper`、`text/event-stream`），见 §4。

## 3. 错误处理（与错误码体系对齐）

错误码段见 `requirements/web/02-错误与异常.md` §1。前端统一策略：

| code 段 | 场景 | 前端行为 |
|---|---|---|
| 1000/1002 | 认证/授权失效 | 外壳层跳转登录（`01-应用外壳与导航.md` §4），不 toast |
| 2000~2003 | 参数/归属/不存在 | toast（danger，`body.message`）；`NOT_FOUND` 类文案保持后端统一句式「xx不存在」 |
| 5000~5003 | 系统/下游异常 | toast（danger，「系统繁忙，请稍后重试」——不直接暴露原始 message） |
| 网络错误/超时 | axios error | 同 5000 段处理 |

约定：

- **错误 toast 是兜底呈现层，唯一实现点在拦截器**——组件内不得绕过拦截器自行 alert/console 渲染错误。
- 表单行内校验（Element Plus form rules）仍前置在组件（ui-baseline §4.2 两级校验）；拦截器 toast 只承接服务端 PARAM_ERROR。
- 需要按 code 做非 toast 分支时（如列表刷新竞态），catch 后按 code 判断，**不改拦截器**。

## 4. SSE 消费（ai-chat 前端）

`POST /chat/sse` 契约：三事件 `message` / `error` / `end`（详见 `specs/ai-chat-spec.md` §2.4、`requirements/ai-chat/03-接口规范.md`）。前端约定：

- 用原生 `EventSource` 不可行（POST + JSON body）→ **fetch + ReadableStream 手解析** 或等价库，实现封装为工程级 `sseClient`（唯一实现，模块复用）。
- 事件分支：`message` 增量渲染；`error` → 按错误 toast 规则（§3）呈现后终止流；`end` → 结束态 + 展示 token 汇总。
- 断连/中断：前端主动 abort（fetch AbortController）；后端事件流结束即视为关闭，无重连逻辑（v1）。
- SSE 流不经过 axios 拦截器，错误呈现仍复用 §3 的 toast 规则。

## 5. 状态管理

- **Pinia，按模块分 store**；跨模块共享状态（当前用户）放全局 store。
- 列表页数据（如任务列表）v1 **不建全局 store**——量级小（≤20）、单页面消费，组件内请求即可；出现跨页共享再升 store。
- 服务端数据缓存 v1 不引入（无 query 库）——数据实时性优先（任务状态流转）。

## 6. 演进

- 契约侧变更（包装形态/错误码段）先改 `requirements/web/`，本文跟随；本文自身变更记 CHANGELOG。
- ai-chat / chat-conversation 前端启动时按本文 + ui-baseline 执行，偏离显式登记（同基线 §5 治理）。
