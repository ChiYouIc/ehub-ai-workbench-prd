# 05 非功能需求与风险 — 会话组与对话内容管理模块

> 模块：chat-conversation ｜ 关联 PRD 母本：`plans/chat-conversation-management-prd.md` (v1.0) ｜ 状态：已定版
>
> 编号规则：`NFR-xx` 非功能需求 / `R-xx` 风险，模块内递增不复用。

## 1. 非功能需求（NFR）

### NFR-01 数据隔离
- 会话组归属校验以 `ai_conversation.crt_user` 为隔离键；不存在 / 非本人 / 已逻辑删除统一报 `NOT_FOUND "会话不存在"`（不泄露他人会话存在性，延续 v1 Q14）
- 接口认证机制见 [`../auth/01-接口认证.md`](../auth/01-接口认证.md)，本模块不重复定义

### NFR-02 安全
- 管理接口为普通 JSON 短任务，**不存在跨线程传递问题**（区别于 SSE 主流程的捕获-重建）
- 响应不泄露其他用户数据、不返回内部列（`tools/params/media_content`）

### NFR-03 分页与性能
- 分页使用 MyBatis-Plus `Page`（需新增 `PaginationInnerInterceptor`，当前未配置）；`maxLimit` 设上限防全表拉取
- 会话组列表**不取最近一条消息摘要**（避免大表子查询，NFR 保障查询成本）；历史内容经详情接口按需分页加载

### NFR-04 可靠性（删除语义）
- 删除为逻辑删除（`is_del=1`），内容行保留不物理删除，审计与成本核算数据不丢
- 已删会话组对外不可见（列表/重命名/历史查询均失效），但数据可追溯

### NFR-05 可观测性
- 关键路径（归属校验失败、删除、分页查询）记日志，含 `conversationId`/userId 便于追踪（延续 v1 NFR-06 风格）

## 2. 风险（R）

### R-01 删除与进行中 SSE 流并发（低）
删除会话组时若恰有 SSE 流正在往该组写内容，内容行照常写入（内容行永不物理删除），已删组不再出现在列表。删除动作不取消进行中的流。
**决策**：接受为 v1 已知边界（Q17）。若后续要求「删除即停流」需评估取消机制，另行评估。

### R-02 分页插件缺失（低）
项目当前未配置 MyBatis-Plus 分页拦截器。若采用 `Page` 分页必须新增 `PaginationInnerInterceptor`，属本功能前置开发项；备选方案为手写 `limit/offset`（不推荐，割裂与 mapper 的集成）。
**缓解**：随本功能（或 v1 开发）补齐分页插件，`maxLimit` 设上限。

### R-03 列表无最近消息摘要（低）
侧边栏无法一屏预览会话摘要，需进入详情查看。
**决策**：Q8 明确不取（避免大表子查询），接受体验取舍。

## 3. 已识别但 v1 不处理

- 会话组无限增长：删除为逻辑删除且内容行保留，库表数据量随时间增长（物理清理 / 归档另议）
- 会话组搜索 / 置顶 / 消息已读 / 消息编辑撤回（Out of Scope）

## 4. Out of Scope 汇总

- 会话组置顶、搜索、消息已读、消息编辑/撤回
- 会话组列表中的「最近一条消息摘要」展示
- 删除会话组时取消进行中的 SSE 流
- 对话内容行物理删除
- 跨用户会话可见性/共享/协作者功能
- 多 Agent/skill 分流、输入内容审核、文件/多模态输入（延续 v1）
