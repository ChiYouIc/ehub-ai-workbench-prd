# 01 接口认证 — 全工程通用约定

> 范围：全工程所有对外接口 ｜ 状态：已定版 ｜ 关联：`GLOSSARY.md`（业务用户 / UserContext / 捕获-重建）
>
> 本文是全工程**接口认证的单一事实源**。所有模块的对外接口均遵循本文约定；各模块文档不重复描述认证机制，仅在此引用。

## 1. 认证方式

- 所有对外接口要求请求头携带 `Authorization: Bearer <JWT>`
- 认证由平台基础设施统一完成：`AuthUserFilter` 解析 JWT → 写入 `UserContext`（ThreadLocal）
- 无有效 JWT（缺失 / 过期 / 非法）的请求 → 认证失败（统一异常包装），不进入业务逻辑

## 2. 用户标识

- 业务代码通过 `UserContext` 获取当前用户标识（`userId` / `username` / `name` 等）
- **客户端不传用户标识**；任何接口不得信任客户端传入的用户身份（防越权）

## 3. 跨线程传递（异步场景）

- 异步线程（如 SSE 长任务运行于线程池）拿不到主线程的 ThreadLocal 上下文
- 标准姿势：**主线程捕获 → 异步线程重建 → 任务结束清理**（捕获-重建）
- 仅异步长任务场景需要；普通同步短任务（如管理类接口）无此问题

## 4. 认证失败错误

| 场景 | 结果 |
|---|---|
| 无有效 JWT / 已过期 / 非法 | 认证失败（统一异常包装），HTTP 层拒绝 |

## 5. 范围与演进

- v1 仅面向业务用户（JWT）；client token 服务间认证不在范围
- 认证机制变更时，先改本文再评估各模块影响；各模块文档只做引用
