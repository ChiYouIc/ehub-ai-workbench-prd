# 01 响应包装 — 全工程通用约定

> 范围：全工程所有对外接口 ｜ 状态：已定版 ｜ 关联：`GLOSSARY.md`、`requirements/auth/01-接口认证.md`
>
> 本文是全工程**统一响应包装的单一事实源**。描述系统对外接口的响应形态与包装机制；实现规则见代码工程 `.agents/skills/web-conventions/`。

## 1. 包装机制

- 所有 `@RestController` / `Controller+@ResponseBody` 的返回值由 `GlobalResponseAdvice`（`ResponseBodyAdvice`）统一包装
- 三档跳过机制：
  1. 类/方法标注 `@SkipWrapper` → 原样返回，不包装
  2. URL 命中 `WebProperties.exclude` 配置（Ant 路径匹配，`?`/`*`/`**`）→ 原样返回
  3. 返回值实现 `ResponseType` 接口 → 已是标准响应形态，不二次包装

## 2. 响应结构

### 成功（普通对象 / 集合）

```json
{ "code": 0, "data": { ... } }
```

`code` 恒为 0（`SUCCESS`）。由 `ApiResponse.success(data)` 构造，返回类型 `SuccessResponse<T>`。

### 成功（无返回）

```json
{ "code": 0, "data": null }
```

由 `ApiResponse.success()` 构造，返回类型 `SuccessResponse<Void>`。

### 成功（分页列表）

```json
{ "code": 0, "total": 100, "data": [ ... ] }
```

由 `TablePageResponse.success(total, data)` 构造，返回类型 `TablePageResponse<T>`。**分页接口一律用此形态**。

### 失败

```json
{ "code": 2002, "message": "未找到", "time": "2026-08-20T10:00:00" }
```

由全局异常处理构造，返回类型 `FailedResponse`（`code`/`message`/`time`）。详见 `02-错误与异常.md`。

## 3. 字符串返回值特殊处理

- Controller 返回 `String` 时，`GlobalResponseAdvice` 手动序列化为 JSON 字符串并设置 `Content-Type: application/json`
- 即字符串也会被包装成 `{"code":0,"data":"..."}`；需要原样文本返回（如 SSE）必须用 `@SkipWrapper`

## 4. 关键类型清单

| 类型 | 包 | 说明 |
|---|---|---|
| `ResponseType` | `core.web` | 标记接口；实现它即免二次包装 |
| `SuccessResponse<T>` | `core.web` | 成功响应 `{code,data}` |
| `TablePageResponse<T>` | `core.web` | 分页响应 `{code,total,data}` |
| `FailedResponse` | `core.web` | 失败响应 `{code,message,time}` |
| `SkipWrapper` | `core.web.response` | 跳过包装注解（方法/类级） |
| `ApiResponse` | `core.web` | 静态工厂：`success()` / `success(data)` |
| `GlobalResponseAdvice` | `core.web.advice` | 统一包装实现 |

## 5. 演进

- 响应形态变更时先改本文，再评估各模块影响；各模块文档只做引用
- 各业务模块新增 VO 时，应复用 `SuccessResponse`/`TablePageResponse` 作为返回类型，不自造包装
