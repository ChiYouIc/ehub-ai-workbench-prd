# 供应商收款账户支付宝对公限制

## Problem Statement

供应商收款账户支持「支付宝」收款方式。当前录入表单对账户名称（持有人姓名）没有格式校验，个人姓名也能保存为支付宝收款账户；币种也不受限制，非人民币币种可以配到支付宝账户上。而公司通过支付宝付款只允许对公付款，问题往往拖到付款执行时才暴露，造成返工与沟通成本。

## Solution

在录入供应商收款账户页面（新增/编辑弹窗）收紧两处校验并调整一处文案，仅当收款方式选择「支付宝」时生效：

1. 账户名称正则校验：必须匹配公司名称格式（以「公司」结尾，如“xxxx公司”）；不符合时提示：**支付宝付款只允许对公付款**。
2. 支付币种限制：仅限人民币（CNY），其他币种不可选。

另有一处全局文案调整：

3. 表单字段标签「持有人姓名」改为「公司名称」（含输入占位符同步改为「请输入公司名称」）。

银行转账、微信等其他收款方式的既有录入行为保持不变。

## User Stories

1. 作为采购/财务人员，我在录入支付宝收款账户时，希望系统校验账户名称必须是公司名称，以免把个人支付宝账户错录成收款账户。
2. 作为采购/财务人员，当账户名称不符合公司格式时，我希望看到「支付宝付款只允许对公付款」的明确提示，以便立刻知道错在哪、怎么改。
3. 作为采购/财务人员，我希望支付宝收款账户的币种只能选人民币，以免配置出无法成功付款的账户。
4. 作为采购/财务人员，当我从其他收款方式切换到支付宝时，我希望已选的非人民币币种被自动清理，以免残留非法组合。
5. 作为采购/财务人员，我在编辑已有支付宝账户时，希望同样的校验生效，以免历史脏数据继续流转。
6. 作为采购/财务人员，我录入银行转账/微信收款账户时，希望新校验不干扰我（仍允许个人姓名与其他币种），以免误伤合法录入。
7. 作为付款操作人员，我希望收款账户里的支付宝账户都是「对公 + 人民币」的，以免付款时才发现账户不可用。
8. 作为供应商管理人员，我希望校验在保存前拦截并精确定位到出错字段，以免提交后才知道失败原因。
9. 作为业务用户，我希望提示文案明确指向支付宝场景，以免误解为所有付款方式都禁止个人账户。
10. 作为开发人员，我希望校验规则集中定义在表单校验层，以免同一规则散落多处造成不一致。
11. 作为采购/财务人员，我希望字段标签直接写「公司名称」而不是「持有人姓名」，以免我在录入支付宝对公账户时误解为可以填个人。
12. 作为采购/财务人员，我希望输入框占位符同步改为「请输入公司名称」，以免占位文案与字段标签不一致。

## Implementation Decisions

- 校验仅作用于供应商收款账户录入弹窗，且仅当收款方式为「支付宝」时触发；银行转账、微信收款方式不引入新校验。
- 账户名称校验：收款方式为支付宝时，账户名称（持有人姓名字段）必须匹配公司名称正则——以「公司」结尾，天然覆盖「有限公司」「有限责任公司」「股份有限公司」等常见企业后缀；不匹配时校验失败，提示文案固定为「支付宝付款只允许对公付款」。
- 币种限制：收款方式为支付宝时，币种下拉仅提供人民币（CNY）一个选项；若切换到支付宝前已选其他币种，自动清空待用户重选，不允许保存非人民币的支付宝账户。
- 校验实现在表单 rules 层（与既有必填校验同层），保存按钮触发表单整体校验，失败即阻断提交；不新增后端接口、不修改数据结构。
- 标签文案：录入表单中「持有人姓名」字段标签改为「公司名称」，输入占位符同步改为「请输入公司名称」。现状为 i18n key 缺失直接回退中文原文（中英文包均无此 key），实现时沿用现有写法补齐对应文案即可，无需改字段名/接口。
- 新增与编辑复用同一表单，编辑已有账户保存时同样执行该校验；不做存量数据批量清洗，存量不合规数据在下次编辑保存时自然被拦截修正。

## Testing Decisions

- 好的测试只验证外部可观察行为：给定收款方式/账户名称/币种的组合，保存是放行还是拦截、提示什么文案；不测内部正则实现细节。
- 唯一测试接缝：供应商收款账户录入表单的校验规则（与必填校验同一层的 validator）。本特性不涉及其他层，不需要新接缝。
- 用例应覆盖：支付宝 + 以「公司」结尾名称 + 人民币（放行）；支付宝 + 个人姓名（拦截并提示指定文案）；支付宝 + 非人民币币种（不可选或被清空）；银行转账/微信 + 个人姓名（不拦截，回归确认）。
- 现状说明：前端仓库当前无自动化测试设施（无测试框架依赖、无现存测试文件）。若需自动化，可将 validator 抽为纯函数做轻量单测；否则以表单手工验证清单作为验收依据。不为一条校验规则搭建整套测试框架属有意决策。

## Out of Scope

- TAPD 原始范围一/二：线下付款审批流提交后系统自动拒绝私户工单并推送提示消息（留待后续迭代）。
- TAPD 原始范围：被系统/人工拒绝的私户任务工单单独 list 查询（留待后续迭代）。
- TAPD 原始范围三：审批人变动时审批页导航条处理人信息不更新的缺陷修复（另行处理）。
- 国内银行账户的对公判断（本期仅支付宝收款方式）。
- 后端/接口层校验（本次仅前端表单拦截）。
- 存量供应商收款账户数据的批量清洗或迁移。
- 付款执行环节（线下转账、账单付款等）对账户合法性的二次拦截。
- 银行转账、微信收款方式的任何新校验。
- 账户名称与工商登记信息的深度比对（如营业执照核验）。
