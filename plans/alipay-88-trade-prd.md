# PRD: 88生意通担保交易（alipay-88-trade）v1.2

> 对应 TAPD 需求（88生意通：1688 平台大额线下采购担保交易）。访谈溯源见 `plans/alipay-88-trade-interview.md`（Q1–Q24，下文引用 `Qn` 均指向该文件）。
> Spike 发现（2026-09-16）：官方 API 清单已验证，结论见 Further Notes「Spike 发现」及 Implementation Decisions 中标注「Spike」的条目。
> 版本：v1.0 初稿 → v1.1 Spike 官方 API 验证 → v1.2 行业方案发现（发货/确认收货消息存在、物流查询 API、线下申请门槛），状态机相应修正。

## Problem Statement

采购团队在线下采购场景（大额、定制类采购）中，货款通过私人账户或对公转账等方式线下打款给供应商，存在以下问题：

1. **资金风险**：线下打款无平台担保，遇到供应商不发货、货不对板时缺乏追索与维权凭证；
2. **凭证缺失**：交易无电子合同、无平台流水，财务对账与审计困难，采购成本难以追溯；
3. **过程不可视**：交易进度（合同签署、付款、发货、结算）在系统内无记录，采购员需在微信等线下渠道反复确认。

1688 官方推出「88生意通」（担保交易 + 电子合同能力，公测期，API 逐步开放），为解决上述问题提供了平台侧基础。

## Solution

在采购单（`purchase_order_batch`）链路上接入 1688「88生意通」担保交易能力：采购员在采购单列表/详情对符合条件的线下采购单人工发起 88生意通交易，系统生成电子合同与收银台支付链接，采购员通过链接完成付款；合同签署、支付、发货、确认完成、结算等全流程状态自动同步回系统并回写采购单；交易流水可按供应商/时间段/状态自动对账，差异告警。

首期限于人民币境内大额/定制类线下采购场景（Q1）；跨境场景继续走现有跨境宝等链路（Q19）。

## User Stories

1. As a 采购员, I want 在采购单详情对符合条件的线下采购单一键发起 88生意通担保交易, so that 我不需要线下私户打款也能获得平台担保与电子合同。
2. As a 采购员, I want 发起后立即获得收银台支付链接并转发给付款同事/自行打开, so that 付款方式可控且有平台凭证。
3. As a 采购员, I want 在采购单详情实时看到 88生意通交易状态（待签署/已签署/待付款/已付款/已发货/已完成/已关闭）, so that 我不用在微信上反复向供应商确认进度。
4. As a 采购员, I want 在交易已付款且卖家已发货后，在采购单详情人工"确认完成"（二次确认）, so that 平台触发结算给卖家，责任留痕。
5. As a 采购员, I want 点击"查看/下载合同"实时获取电子合同文件, so that 我随时可以取用合同凭证而不依赖本地存档。
6. As a 采购员, I want 发起前系统校验供应商档案已维护 1688 卖家账号且与交易对方匹配, so that 避免合同签错主体。
7. As a 财务人员, I want 系统自动对账任务每日将本地 88生意通交易流水与平台流水比对并告警差异, so that 我不需要人工逐笔核对。
8. As a 财务人员, I want 按供应商/时间段/状态筛选并导出 88生意通交易流水, so that 我可以完成月度审计与成本核算。
9. As a 运营管理员, I want 通过功能开关+白名单（指定采购员/供应商）灰度放量, so that 新链路风险可控。
10. As a 系统管理员, I want 88生意通逆向状态（合同撤回/未付款取消/交易关闭）自动回写采购单（回退待处理/关闭）并留痕原因, so that 采购单状态不与平台脱节。
11. As a 采购员, I want 发起前系统校验我方 1688 账号已完成 88生意通认证并给出引导, so that 我不会在起草合同后才发现无法签署（Spike）。

## Implementation Decisions

（溯源：每条标注访谈 Qn）

### 业务范围与发起

- **首期范围**：仅大额/定制类线下采购的人民币境内担保交易；账期支付、分阶段支付不做（Q1、Q19）。
- **发起方式**：采购单人工发起（列表+详情入口），不做自动转担保，不做批量发起（Q2、Q15）。
- **发起流程**：官方为两步接口（买家起草采购单 → 买家确认采购单），系统封装为一次用户操作，中间态失败可重试（Spike）。
- **买家认证前置校验**：发起前调用认证状态查询接口校验我方 1688 账号已完成 88生意通实名认证，未认证给出引导提示（Spike）。
- **交易粒度**：采购单:担保交易 = 1:1，一张采购单最多存在一笔进行中的 88生意通交易（Q14）。
- **存量数据**：不迁移、不补录历史线下单（Q21）。

### 数据模型

- **并入付款单体系**：`bill_payment` 新增「88生意通」类型，88生意通交易信息（平台交易号、合同号、支付链接、合同/交易状态、手续费配置）作为字段直接落在付款单上，**不建独立子表**（Q3、Q13）。字段命名以 `ali_88_` / `syt_` 前缀规约为准，实现期若字段膨胀可重评估拆表（见 Further Notes）。
- **采购单回写**：担保交易状态变化回写 `purchase_order_batch`（状态回退/关闭、支付信息），保持采购单列表可见汇总状态。
- **供应商映射**：`Supplier` 档案新增维护对应 1688 卖家账号（memberId/loginId）能力，发起时校验匹配（Q4）。

### 支付与合同

- **支付**：仅收银台链接模式（生成链接 → 人工打开支付）；免密代扣不做（Q5）。不设额外金额硬限制，风控依赖现有采购付款审批流（Q23）。
- **合同**：查看/下载时实时调平台接口获取，不落 OSS 存储（Q18）；支付链接同样实时获取不缓存长存。
- **手续费**：费率/承担方为可配置项，默认关闭（不计入采购成本）；官方口径确认后配置启用（Q6）。

### 状态同步与对账

- **状态同步**：复用现有 1688 推送链路（WebSocket → MQ → 消息处理组件 → 按消息类型路由），SYT_* 消息（待签署/签署成功/支付成功/拒绝/退款结果/交易存证/卖家上传物流单号/买家确认收货成功）在其中扩展路由；发货状态由 `SYT_SELLER_LOGISTICS_UPLOADED` 消息驱动、交易详情轮询兜底；确认完成结果以 `SYT_BUYER_CONTRACT_CONFIRM_SUCCESS` 消息回执确认；推送与轮询幂等合并回写（Q7，消息清单经行业方案 Spike 确认，见 v1.2 修正）。
- **自动对账**：定时任务拉取平台流水与本地比对，差异产出告警与差异清单（Q10，用户明确选择超出"仅导出"的深度）。
- **逆向处理**：合同撤回/未付款取消/交易关闭等状态回写采购单（回退到待处理/关闭），原因留痕；售后退款走线下+记录，不建自动退款链路（Q11）。

### 权限与灰度

- **权限**：对齐现有采购单付款权限体系，不新增独立权限点（Q16）。
- **灰度**：功能开关（默认关）+ 采购员/供应商白名单，灰度验证后全量（Q22）。

### 第三方边界

- 88生意通有**两个方案入口**（均为「采购服务商」身份，同一开放平台鉴权体系，token/权限管理沿用现有机制）：
  1. 「88生意通解决方案（买家自用版）」行业方案（solutionKey=1768380628346，v1.9）——**正式对接目标**，API/消息清单更完整（见 v1.2 修正）；**申请门槛：需线下联系 88生意通运营团队申请**，这是项目前置条件；
  2. 「跨境综合解决方案（自用）」（solutionKey=1697014160788，v17.8）——现有跨境模块已订购，其 88生意通子集可作为备选降级路径（无发货消息、无物流查询 API，但含万里汇支付）。
- 接口清单层面的剩余不确定项收敛为两个沙箱验证点：合同文件获取方式、平台流水/对账查询能力（见 Further Notes 风险与缺口）；验证结论若引起范围变化需升版 PRD（Q12、Q20）。

## Testing Decisions

- **优先测试行为**（外部行为而非实现细节）：
  1. 发起链路：符合/不符合条件采购单的发起校验（供应商 1688 账号匹配、1:1 约束、灰度开关与白名单）；
  2. 状态回写：模拟平台各状态推送/轮询结果 → 采购单与付款单状态收敛正确且幂等（重复推送不产生副作用）；
  3. 逆向回退：取消/关闭回写采购单状态与留痕；
  4. 对账差异：构造本地/平台流水差异，验证告警与差异清单产出；
  5. 手续费开关：开启前后采购成本计算差异。
- **测试参照**：现有 1688 消息处理与状态回写的测试模式（`ehub-tenant` 中针对订单状态同步的测试）、`CostControlPurchaseGoodsAmountSyncServiceImplTest` 一类的服务级单测风格。
- **契约测试**：88生意通 API 响应结构以 Further Notes「Spike 发现」的接口能力矩阵为契约基线，mock 平台响应做回放测试（两步发起、收银台 URL、状态查询优先覆盖）。

## Out of Scope

- 账期支付、分阶段支付（待官方开放后另起需求）（Q1）；
- 免密代扣支付（Q5）；
- 批量发起与失败回执重试（Q15，需求待定）；
- 跨境支付渠道（跨境宝等现有链路不变）（Q19）；
- 自动确认完成/自动退款售后链路（Q8、Q11）；
- 存量线下采购单补录迁移（Q21）；
- 合同文件本地/OSS 存储归档（Q18）；
- 新增独立权限点体系（Q16）。

## Further Notes

- **Spike 发现（2026-09-16，来源：官方方案页「跨境综合解决方案（自用）」solutionKey=1697014160788，方案版本 17.8）**：

  **鉴权形态确认（对应 Q9）**：88生意通 API 归属「跨境综合解决方案（自用）」——与现有跨境模块同一方案体系（appKey/secret + token），鉴权沿用，无需新增 token 监控需求；需在控制中心确认生产 appKey 的订购版本已包含 88生意通 API 权限。

  **接口能力矩阵（对应 PRD 功能点）**：

  | PRD 功能 | 官方 API | 结论 |
  |---|---|---|
  | 发起担保交易 | `syt.buyer.draftPurchaseOrder`（买家起草采购单）+ `syt.buyer.confirmPurchaseOrder`（买家确认采购单） | ✅ 两步流程，封装为一次操作 |
  | 收银台支付链接 | `syt.contract.pay`（买家支付获取收银台 URL） | ✅ 与 Q5 匹配 |
  | 确认交易完成 | `syt.contract.confirm` | ✅ 与 Q8 匹配 |
  | 合同作废/取消 | `syt.contract.invalid` | ✅ 逆向回写有官方入口 |
  | 退款申请 | `syt.contract.refund`（合同退款申请） | ⚠️ 平台能力已具备，首期仍按 Q11 走线下+记录，后续可线上化 |
  | 交易状态查询 | `syt.buyer.queryContractDetail`（买家查询采购单详情） | ✅ 轮询兑底与详情展示可用 |
  | 买家认证校验 | `syt.customer.queryUserAuthStatus`（查询客户是否已认证） | ✅ 新增发起前置校验（用户故事 11） |
  | 跨境转账支付 | `syt.contract.payTransfer`（万里汇 B2C） | ⏸ 后备选项，首期不做（Q19） |

  **消息推送确认（对应 Q7，v1.2 按行业方案修正）**：SYT 系列消息在现有推送体系内。行业方案（买家自用版）比跨境方案多三条关键消息：`SYT_SELLER_LOGISTICS_UPLOADED`（商家上传物流单号，即「卖家已发货」专用消息——v1.1 记录的缺口不成立）、`SYT_BUYER_CONTRACT_CONFIRM_SUCCESS`（买家确认收货成功回执）。完整清单：`SYT_CONTRACT_WAIT_SIGN`（待签署）、`SYT_CONTRACT_SIGN_SUCCESS`（签署成功）、`SYT_CONTRACT_PAY_SUCCESS`（支付成功）、`SYT_CONTRACT_REJECT`（拒绝）、`SYT_SELLER_LOGISTICS_UPLOADED`（卖家上传物流单号）、`SYT_BUYER_CONTRACT_CONFIRM_SUCCESS`（确认收货成功）、`SYT_REFUND_FINISH_NOTICE`（退款结果）、`SYT_ADD_CONTRACT_CONTENT`（交易存证）。

  **行业方案补充发现（2026-09-16，v1.2）**：
  - 行业方案（solutionKey=1768380628346，v1.9，2026-07-22 更新）为正式对接目标，API 清单新增 `syt.buyer.queryLogisticsTrace`（买家主动查询物流单号），但**不含**万里汇 `syt.contract.payTransfer`（跨境方案专属，与 Q19 不做的决策一致）；
  - **申请门槛：线下联系 88生意通运营团队申请**——非纯线上订购，需提前启动商务流程，列入项目前置条件与工单；
  - v1.1 的「无卖家发货消息」缺口结论仅适用于跨境方案；按行业方案接入后，发货状态消息驱动 + 轮询兜底。

  **剩余风险与缺口（沙箱验证点，任一坐实则升版 PRD）**：
  1. **合同文件下载**（Q18）：接口清单未见独立的合同文件下载 API——需验证 `queryContractDetail` 是否返回合同文件/查看链接；若不返回，Q18 降级为跳转平台页面查看；
  2. **流水/对账查询**（Q10 自动对账）：未见批量流水查询 API——可能需降级为「逐单 `queryContractDetail` + 本地流水比对」，或依赖消息补偿接口（`push.cursor.messageList`）重建平台侧事件流做对账；
  3. **方案订购版本**：API 随方案版本迭代（17.8，2026-08-25 更新），需确认生产 appKey 订购范围包含 88生意通权限包。
- **付款单字段膨胀风险**：Q13 选择全部信息存 `bill_payment`；若实现期发现字段数超预期（合同+状态+链接+手续费），允许在 spec 阶段重评估拆子表，需回本 PRD 升次版本记录。
- **TAPD 待确认项回写**：手续费率/承担方（待确认项 2）、API 开放范围（待确认项 1）、跨境渠道（待确认项 3）在 spike 结论明确后回写 TAPD 评论。
