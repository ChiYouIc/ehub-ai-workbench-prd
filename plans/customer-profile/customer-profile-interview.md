## 决策要点（PRD 输入）

### 对象与转化
- 入池 = 已注册且未消费（无已支付订单）；出池 = 首单**支付成功**（下单未付仍在池内，属催单场景）
- 出池后画像冻结保留、详情可回看；列表默认只显示池内客户
- 既有 `tag`/`level` 只读消费，AI 不回写业务表

### 触发（v1 纯手动）
- 入口 = 老系统检索列表行内「生成画像」+ 详情页「重新生成」；仅单个触发，无批量
- 无定时扫描、无周期重扫、无自动全量回填（全部 → v2）
- 触发时经工具①实时校验消费状态；已出池客户不可触发；分析进行中幂等拒绝（`PARAM_ERROR "分析进行中"`）

### 数据与下游
- v1 数据源 = `customer` + `customer_extend` 两表；行为日志 → v2
- 下游 MCP 工具最终 **1 个**：新用户信息（两表合并 + 消费状态字段）；统计口径归数据属主
- 老系统用户检索接口接入新页面（池发现权归老系统）

### 前端（双列表，宿主业务系统承载）
- 老系统检索列表（找客户 + 触发生成）+ 本服务画像列表（五筛选：质量/热度/优先级/完整度/转化阶段；默认排序 follow_priority 升序 + generated_at 降序，未生成排最后）
- 卡片七区块沿用业务线框：Header（含**转化阶段标签**：未绑店 / 已绑店未首单）→ 评分面板（AI×3 + 规则×1）→ 基础画像 → 线索速读 → 转化策略 → 销售话术 → Footer
- 基础画像七字段：DS 经验 / 周广告预算 / 月订单量预期 / 细分市场 / 意向服务 / 最近登录 / 绑定店铺（**无订单数/成交额**）；渠道归因进 Header Meta
- skill 按转化阶段硬分流生成策略 + 话术

### 存储与质量纪律
- 表 `ai_customer_profile`（基名直接继承）；`profile_json` 整包 + 五投影列（lead_quality / intent_heat / follow_priority / info_completeness + 转化阶段）
- 沿用基线：覆盖式 upsert 只留最新、固定 schema 强校验失败即弃（重试 1 次）、无冷却期、model+input/output token 审计、`infoCompleteness` 规则计算（四层基准、问卷五项约 60% 权重）、skill 禁虚构意向信号/禁硬承诺
- 冷启动照常分析（速读声明「数据有限，结论仅供参考」），不设门槛、无降级落库
- 验收五条：① 手动触发出画像成功率（含重试）≥95% ② 抽检 50 客户 leadQuality/followPriority 与资深销售一致率 ≥80% ③ 话术抽检零硬承诺 ④ 五筛选键可用 ⑤ token 全量记录

### v2 边界（Out of Scope，Q22 照单全收）
行为日志数据工具 / 定时扫描 + 自动全量回填 / 批量触发 / 评分漂移约束 / 历史版本保留 / 话术 scripts[] 数组化 / 已转化客户复盘分析 / 角色·线索归属隔离
