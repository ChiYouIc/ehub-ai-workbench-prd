# PRD: 客户画像信息架构（customer-profile-ia 模块）

> 状态：**v0.1（草案）** — 2026-08-25
> 前置依赖：现有 MCP 统计服务（CRM 基础信息 + 行为日志扩展）；百炼 Agent。
> 关联模块：`customer-profile`（代发客户运营画像，独立 PRD，并行存在，同一批客户两套画像）。
> 信息架构草图：`designs/customer-profile/customer-profile-ia.pen`

## Problem Statement

销售团队面对大量注册线索（含已绑定代发客户），缺乏系统化的客户认知：不知道哪个线索质量高、意向强弱、该用什么样的话术跟进。目前完全依赖销售个人经验判断，效率低且标准不统一。

**目标**：为每个客户生成一张**结构化画像卡片**，涵盖评分、速读、策略建议、可复制话术，帮助销售快速了解客户并决定下一步行动。

**与 customer-profile 的关系**：同一批客户同时存在两套画像——customer-profile-ia 面向**销售转化**（线索质量/意向/策略/话术），customer-profile 面向**运营分层**（价值/生命周期/流失风险）。两套画像独立生成、独立存储、独立演进。

## Solution

在 `ehub-ai-workbench` 服务中新增**独立模块 `customer-profile-ia`**：

### 1. 画像卡片信息架构（7 个模块，按字段条件显隐）

| # | 模块 | 内容 | 数据来源 | 降态（FALLBACK） |
|---|---|---|---|---|
| 1 | Header | 邮箱 + ID + 激活状态徽章 | MCP CRM 基础信息 | 正常显示（非 AI） |
| 2 | Meta | 国家·注册天数·渠道·等级·绑定状态 | MCP CRM 基础信息 | 正常显示（非 AI） |
| 3 | **评分面板** | 线索质量 / 意向热度 / 跟进优先级 / 信息完整度 | **AI 生成** | 基础数据兜底（信息完整度规则算，其余标 N/A） |
| 4 | **线索速读** | 一段话概括客户特征与转化机会 | **AI 生成** | 显示“AI 暂不可用”提示 |
| 5 | 经验与预算画像 | DS 经验 / 周广告预算 | 用户填报 + MCP | 正常显示（无数据填“未提供”） |
| 6 | 目标市场与品类 | 细分市场 / 主营品类 | 用户填报 + MCP | 正常显示（无数据填“未提供”） |
| 7 | 活跃轨迹 | 累计登录 / 最近登录 / 激活状态 | MCP 行为日志 | 正常显示（非 AI） |
| 8 | **转化策略建议** | 针对性转化策略 | **AI 生成** | 显示“AI 暂不可用”提示 |
| 9 | **销售话术** | 可复制的一段跟进话术 | **AI 生成** | 显示“AI 暂不可用，请稍后刷新” |
| 10 | Footer | 生成时间 + aiStatus（SUCCESS/FALLBACK） | 系统元数据 | 正常显示 |

### 2. AI 生成能力

通过百炼 Agent 调用，输入客户数据（CRM + 行为日志 + 用户填报），输出 4 个 AI 模块：

- **评分面板**（4 项全部 AI 综合判断，非规则计算）
  - `leadQuality`：高/中/低
  - `intentHeat`：热/温/冷
  - `followPriority`：P0/P1/P2/P3
  - `infoCompleteness`：0~100%（AI 基于可用字段综合评估）
- **线索速读**（`reading`）：≤300 字中文概括
- **转化策略建议**（`strategy`）：≤300 字中文策略
- **销售话术**（`script`）：≤500 字中文可复制话术

### 3. 触发机制

- **定时批量生成**：复用 `@Scheduled` + DB 行级原子抢占模式（同 customer-profile / scheduled-task），定期对新增/更新客户批量生成画像
- **手动刷新**：REST API 触发单客户重新分析（销售在详情页点击刷新）
- **FALLBACK 触发**：AI 调用失败（超时/校验失败/重试后仍失败）→ 评分面板基础数据兜底 + AI 模块显示“暂不可用”

### 4. 存储方案

新建独立表 `ai_customer_profile_ia`，与 `ai_customer_profile` 完全分开。

## User Stories

1. 作为销售人员，我想在客户详情页看到结构化画像卡片（评分/速读/策略/话术），以便快速了解客户并决定下一步
2. 作为销售人员，我想复制 AI 生成的销售话术直接使用，减少话术准备时间
3. 作为销售人员，我想看到每个客户的评分面板（质量/热度/优先级/完整度），以便批量筛选和排序跟进对象
4. 作为销售人员，我想手动刷新某个客户的画像，以便获取最新分析结果
5. 作为系统管理者，我想让画像定时批量预生成，以便销售打开详情页时无需等待
6. 作为系统管理者，我想在 AI 不可用时显示 FALLBACK 降态而非报错，以保证销售体验连续

## Key Design Decisions

> 以下为初始草案决策，待 Grilling 访谈确认。

1. **独立模块**：与 customer-profile 并行，不复用表/接口
2. **独立存储**：新建 `ai_customer_profile_ia` 表
3. **AI 全量生成**：评分面板 4 项全部 AI 综合判断（非规则计算），信息完整度也是 AI 评估
4. **数据源复用 MCP**：CRM 基础信息 + 行为日志通过现有/扩展 MCP 服务获取
5. **FALLBACK 语义**：仅 AI 调用失败时降级（数据不足不触发 FALLBACK，AI 可基于有限数据输出）
6. **双触发**：定时批量 + 手动刷新
7. **profile_json 整包存储**：沿用 customer-profile 的存储形态（整包 JSON + 检索投影列）
8. **aiStatus 字段**：SUCCESS / FALLBACK，前端据此控制 AI 模块显隐

## Open Questions（待 Grilling）

1. 评分面板 4 项的 AI 判断依据/规则由 skill 定义还是另有配置？
2. 定时批量生成的周期？（每日/每小时？全量还是增量？）
3. MCP 服务是否已具备 CRM 基础信息 + 行为日志 + 用户填报的数据工具？还是需要新定义？
4. 评分面板的 4 项是否需要作为检索/筛选键？（影响投影列设计）
5. 转化策略和销售话术的 AI 生成是否有合规/安全风险？（话术内容可能涉及承诺）
6. 与 customer-profile 的两套画像是否需要在同一页面并排展示？
7. 话术长度上限 500 字是否合适？
8. 信息完整度 AI 评估的基准字段清单？
