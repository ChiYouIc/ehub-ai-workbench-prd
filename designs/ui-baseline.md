>
> 本文档是**全工程 UI 基线 founding 文档**：色彩 token、状态色映射规则、布局范式、治理规则在此统一维护。各模块 UI 设计文档（`designs/<feature>/<feature>-ui-spec.md`）必须继承本文档，只做模块实例化与显式登记的偏离。基线与模块文档冲突时**以本文档为准**；文档与原型/实现冲突时**文档优先**（§5）。

## 1. 设计基线声明

- **组件库**：Element Plus（Vue 3）。v1 不做视觉重绘，**「Element Plus 默认值」即本工程 v1 视觉规范**。
- **字体/间距/圆角/阴影**：全量沿用 Element Plus 默认 token，不自定义。
- **定制范围**：仅「色彩语义映射规则」（§3）与「布局模式」（§4）两部分为工程级约定。

## 2. 色彩 Token（v1 = Element Plus 默认值转正）

| Token | 值（Element Plus 默认） | 语义用途 |

## 3. 状态色彩语义映射规则（工程级 ★）

**映射原则**：领域状态 → Element Plus 语义色（success / info / primary / danger / warning）。各模块 ui-spec 按此规则落成本模块映射表（形态：领域状态 ｜ 组件 ｜ 语义色 ｜ 说明），映射表必须可回溯到模块状态机（`-design.md`）与状态展示表（`-ia.md`）。

规则：

1. **状态色只用语义色，不用裸色值**——实现一律 `type="success"` 等，禁止硬编码 hex。
2. **持续态与瞬时态分色**：持续有效状态用 success（绿），瞬时进行态用 primary（蓝）——避免「绿 = 一切正常」的歧义。
3. **空值/未发生**：文本占位「—」，secondary 灰；不渲染 tag。
4. **危险固定 danger**：不可逆操作按钮固定 danger 语义；其确认对话框内主按钮承接 danger。
5. **错误反馈统一 toast + danger**：PARAM_ERROR / NOT_FOUND 等服务端错误经 el-message（danger）呈现，不做侵入式弹窗；NOT_FOUND 类文案统一「xx不存在」句式（模块定语由模块 ui-spec 定义）。
6. warning 暂无落位（预留），启用前须回填本表用途说明。

## 4. 布局模式（工程级 ★）

### 4.1 列表页三段式

```
┌──────────────────────────────────────────────┐
│ 工具条（搜索 / 筛选 / 主操作）                  │
├──────────────────────────────────────────────┤
│ 表格主体                                      │
├──────────────────────────────────────────────┤
│ 分页器                                        │
└──────────────────────────────────────────────┘
```

- 列表页 = 工具条 + 表格 + 分页（三段式，外壳内主体区），工程级列表页范式。
- **应用外壳不入模块草图与原型**：侧边导航（全局导航）由前端应用框架层统一提供，模块设计只负责外壳内的主体区。
- **结构化配置独立成列**：cron 这类可扫读的机器配置不与业务名混排，独立列呈现（次要文本/等宽字体）——列宽充足时优先独立列，列宽紧张时才考虑双行压缩。

### 4.2 表单对话框模式

- el-dialog + el-form（label 位置与尺寸随 Element Plus 默认）。
- 长文本字段：textarea + **右下角字数统计**（`n / 上限`）。
- **配置类字段用「预设选择 + 联动细化」复合输入范式，不暴露底层表达式/机器格式**——选择结果由前端组装为接口契约字段提交，后端仍按原语义校验。
- 开关语义字段：el-switch，**开关旁必须标注当前语义后果**（开/关各意味着什么领域行为）。
- 校验两级：行内前置校验（Element Plus form rules）+ 服务端 PARAM_ERROR toast 兜底。

### 4.3 确认对话框模式

- 危险/不可逆操作必须经确认对话框，**对话框文案必须陈述领域语义后果**（不是通用的「确定吗」）。
- **工程级文案规范：确认框 = 语义后果声明，不是流程装饰。**

### 4.4 反馈模式

- 操作成功/失败：toast（el-message），不做侵入式弹窗。
- 异步动作：确认即返回，**列表行状态自行流转**（瞬时态 tag 呈现），无进度条。

## 5. 继承与治理

1. **模块 ui-spec 必须继承本文档**：色彩引用 §2 token、状态映射遵循 §3 规则落模块映射表、布局引用 §4 范式编号做模块实例化；不另起炉灶。
2. **变更规则**：token 级变更只动 §2 表；规则/范式级变更在 §3/§4 修订并记 CHANGELOG（各模块 ui-spec 随动）；**模块偏离必须显式登记**（模块 ui-spec 注明「偏离基线 §x.y，理由 …」），禁止静默漂移。
3. **文档优先于原型与实现**：`.pen` 原型、前端实现与本文档冲突时以文档为准，发现冲突应回改原型/实现。
4. v1 明确不做：暗色模式、自定义字体、视觉品牌化——留待有真实诉求时按 token 体系扩展。
