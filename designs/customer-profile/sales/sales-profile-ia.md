## 1. 设计定位

- 两个页面：**客户列表页**（搜索 + 四键筛选 + 画像摘要表）与**画像卡片详情页**（七区块卡片）。两页均由宿主 CRM 承载；本仓库锁定信息架构与交互语义。
- 数据语义：`profile=null` ⇔ 空态页（宿主渲染空态 + 手动触发入口，Q14-①）；卡片实时区块 = 接口 `basic` 数据（Q14-②A），与画像生成解耦。
- 评分面板 3 项 AI 评分 + 1 项规则计算（`infoCompleteness` 非 AI 产出，FR-08）——卡片内「AI 评估 / 规则计算」小字来源标注可区分。
- 列表页四筛选键（leadQuality/intentHeat/followPriority/infoCompleteness）口径 = 接口 `GET /profile/sales/list` 查询参数（验收 3）。
- 未承诺部分：任务中心/消息通知（宿主自有能力，PRD Out of Scope）；RUNNING 期间列表项态由宿主选配（非锁定项，05 §R-04）。

要点：

- **工具条**：搜索框（邮箱 / 客户 ID）+ 四筛选键 + 重置。**搜索框定位（F-1 修订）**：宿主 CRM 客户定位入口——命中后跳转该客户 P2 详情页，**不作用于画像列表**（list 接口无搜索参数，邮箱亦不存画像表）；四筛选键 = 接口四查询参数（验收 3），完整度为区间筛选 `infoCompletenessMin/Max`（F-2 修订，0~100 闭区间可单边）。
- **表格 7 列**：客户（邮箱 primary 色 + ID/绑定 tag 副行；邮箱/客户名由宿主 CRM 按 customerId 富化——列表 VO 不含邮箱，F-3 注记）、线索质量、意向热度、优先级（三列均 tag 语义色）、完整度（数值）、线索速读（截断 + 悬浮全文）、生成时间。

- 排序默认优先级升序 + 生成时间降序（Q24）；行点击 → 详情页。
- 空结果 `total=0, data=[]` 正常渲染空表格；分页器右对齐（总数 + 页码）。

区块字段映射（→ `SalesProfileDetailVO`，03 §4）：

| 区块 | 内容 | 数据来源 | 空值语义 |
|---|---|---|---|
| ① Header | 邮箱 + 激活 tag；Meta tag 行（ID/国家·注册天数/渠道/等级/绑定）；操作区：刷新（实时数据）+ 重新生成（触发分析） | 邮箱归宿主 CRM；Meta = `basic` | 缺项不渲染对应 tag |
| ② 评分面板 | leadQuality/intentHeat/followPriority（值 + 「AI 评估」小字）+ infoCompleteness（值 + 「规则计算」小字） | `profile` | 空态页不渲染 |
| ③ 基础画像 | 2×3 描述表：最近订单数量/消费金额/DS 经验/周广告预算/累计登录/最近登录（r6 移除工单数量/主营品类/细分市场） | `basic` | null → 「未提供」 |
| ④ 线索速读 | reading ≤300 字，浅蓝底框（AI 感知色） | `profile` | — |
| ⑤ 转化策略 | strategy ≤300 字 | `profile` | — |
| ⑥ 销售话术 | script，**多条独立卡片**，每条尾部复制按钮 | `profile` | — |
| ⑦ Footer | analyzeTime · triggerSource · model，placeholder 灰 | `profile` | — |

设计原则：

- **来源标注**：(AI×3 + 规则×1) 说明 tag、区块级 [AI] tag、「AI 评估/规则计算」卡片小字三层标注——防误读（R-05）。
- **多条话术**：话术区块为**卡片列表**语义，条数不固定（v1 接口 `script` 为单字符串，多条展示 = 宿主切分或 v2 扩展为数组；当前以 ≤500 字整段为基准，多条时各条独立复制）。
- **Header 操作区**：刷新 = 重取 basic 实时数据；重新生成 = 重新触发分析（覆盖式 upsert，无冷却，PRD 决策 14）——与 v1.0「不设重新生成入口」修订为**显式入口**。
- token 审计字段（inputToken/outputToken）不展示。

### 3.3 P2-Empty 空态（无画像）

```
┌──────────────────────────────────────────────────────────────┐
│ ① Header（同 §3.2——实时数据不依赖画像）                       │
├──────────────────────────────────────────────────────────────┤
│              （居中引导区）                                    │
│        该客户还没有销售画像                                    │
│   生成画像约需 1 分钟 · 成功后自动展示（基础信息不受影响）       │
│              [ 生成画像 ]（primary 主按钮）                    │
├──────────────────────────────────────────────────────────────┤
│ ⓘ 空态判定：data.profile=null（HTTP 200）；点击生成 POST       │
│   analyze（MANUAL）；失败 toast 报错并停留空态。               │
└──────────────────────────────────────────────────────────────┘
```

要点：

- 空态判定 = `GET /profile/sales/{customerId}` 返回 `data.profile=null`（HTTP 200，非错误）；Header 照常渲染。
- **错误态 ≠ 空态（F-4 修订）**：客户不存在（`NOT_FOUND "客户不存在"`，MCP 查无）为错误态——toast/错误页呈现归宿主裁量，不渲染空态页（空态仅指客户存在而无画像）。
- 「生成画像」→ `POST /profile/sales/{customerId}/analyze`（trigger_source=MANUAL，不限活跃集 Q12）；点击后 loading 不离开页面。
- Alert 条（info 描边）常驻展示判定语义——向宿主开发者显式说明空态≠错误。
- 已有画像详情页的重新分析走 Header 操作区「重新生成」（§3.2）。
