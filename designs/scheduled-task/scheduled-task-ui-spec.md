## 2. 状态色彩映射（基线 §3 规则 → 本模块映射表）

依据 `scheduled-task-design.md` §3 状态机与 `scheduled-task-ia.md` §5 状态展示表，按基线 §3 规则落成本模块映射：

| 领域状态 | 组件 | 色彩语义 | 说明 |
|---|---|---|---|
| `status=ENABLED`（启用） | el-tag | success | 绿 |
| `status=DISABLED`（停用） | el-tag | info | 灰；伴随 `nextFireTime` 显示空 |
| `run_state=RUNNING`（执行中） | el-tag | primary | 蓝；「立即执行」操作禁用 |
| `last_run_status=SUCCESS` | el-tag | success | 绿 |
| `last_run_status=FAILED` | el-tag | danger | 红；鼠标悬停/次行展示 `lastRunError` 摘要 |
| `last_run_status=null`（未执行过） | 文本占位 | secondary | 灰色「—」 |
| PARAM_ERROR（含配额超限） | el-message / toast | danger | 红 |
| NOT_FOUND（任务不存在） | el-message | danger | 红；统一文案「任务不存在」 |

模块附注：「执行中」为瞬时态（至多一个任务处于 RUNNING），主色蓝与启用绿分色呈现——基线 §3 规则 2 的本模块落位。

## 3. 布局范式实例化（基线 §4 → 本模块）

### 3.1 列表页三段式（基线 §4.1 → P1）

- 工具条：搜索任务名 / 状态筛选（全部/启用/停用）/ 主操作「＋新建任务」
- 表格列（六列）：名称（单行，primary 文本）/ 状态 tag / **执行计划**（cron 表达式，secondary 等宽字体）/ 下次执行 / 最近执行（时间+结局）/ 操作（执行/编辑/删除）
- 「执行」动作在 `run_state=RUNNING` 时禁用（守卫前置到交互层，服务端 PARAM_ERROR 兑底）
- 分页器：量级 ≤20，通常单页

### 3.2 表单对话框（基线 §4.2 → P2）

- 长文本字段（prompt）：textarea + **右下角字数统计**（`n / 8000`）
- 执行时间字段：**频率单选（每天/每周/每月，无自定义）+ 随频率联动的时刻选择（精确到分钟）** + 下次执行预览——复合输入控件范式；不暴露 cron 表达式输入，前端组装 cronExpression 提交
  - 组件映射：频率 = el-radio-group；时刻 = el-time-picker（`format="HH:mm"`，分钟粒度）；星期 = el-select（周一~周日）；日期 = el-select（1~31 号）；预览 = 只读文本（提交前实时计算）
  - 频率 ↔ cronExpression 组装对照（提交前由前端组装，后端仍按 Spring cron 校验间隔 ≥5 分钟）：

    | 频率 | 用户选择 | cronExpression |
    |---|---|---|
    | 每天 | 09:00 | `0 0 9 * * *` |
    | 每周 | 星期五 01:00 | `0 0 1 ? * FRI` |
    | 每月 | 1 号 03:00 | `0 0 3 1 * *` |

  - **每月 31 号的未命中月**：cron 天生跳过（2 月等无 31 号的月份当月不触发），UI 不特殊处理、不提示——预览展示的是真实下次执行时间，用户可自行发现；这是有意接受的行为
  - **编辑回填**：后端仅存 cronExpression，前端解析回预设（每天/每周/每月 + 时刻）；解析失败（历史数据或非预设可表达的表达式）时降级为「每天 00:00」并高亮提示用户重新确认——不可静默保存
- 开关语义字段（创建即启用 / enabled）：el-switch，**开关旁必须标注当前语义后果**（如停用 → 不再排程）
- 校验：行内前置校验（Element Plus form rules）+ 服务端 PARAM_ERROR toast 兜底

### 3.3 确认对话框（基线 §4.3 → P3/P4）

本模块两处语义后果声明文案：

- 删除（P4）：「绑定的会话组及其历史内容将保留，仍可在会话历史中查看」「若正在执行，本轮将继续完成」
- 立即执行（P3）：「不影响原计划排程（下次执行时间不变）」「本次产出将标记为『手动触发』」「执行异步进行，可在列表查看执行状态」

### 3.4 反馈（基线 §4.4 → 本模块 toast 文案）

- 配额超限：「任务数量已达上限（20 个），请先删除不再需要的任务」（danger）
- 字段非法：随 PARAM_ERROR 返回信息呈现（danger）
- NOT_FOUND：「任务不存在」（danger）

## 4. 组件状态清单（供走查）

| 组件 | 需覆盖状态 |
|---|---|
| 任务行 | 启用/停用 × 空闲/执行中 × 最近执行 成功/失败/无 |
| 「立即执行」按钮 | 可用 / 执行中禁用 |
| 表单字段 | 空 / 合法 / 越界（长度、cron 间隔）/ 服务端错误 |
| 列表 | 有数据 / 空列表（total=0 呈现空态而非错误） |
| 分页 | 单页（分页器隐藏或禁用）/ 多页 |
