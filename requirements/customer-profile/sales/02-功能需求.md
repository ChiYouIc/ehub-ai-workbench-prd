# 02 功能需求 — 销售转化画像模块

> 模块：customer-profile-sales（销售转化画像） ｜ 关联 PRD 母本：`plans/customer-profile/customer-profile-sales-prd.md`（v1.1 已定版） ｜ 状态：随定版生效
>
> 编号规则：`FR-xx`，模块内递增不复用。验收标准描述**外部可观察行为**。错误码沿用既有 `PARAM_ERROR / NOT_FOUND`，不新增。

## FR-01 生成销售画像（核心流水线）

**需求**：对指定活跃/绑定客户执行一次完整分析，产出销售画像落库。

**验收标准**：
1. 触发来源两种：SCAN（定时扫描命中，FR-03）/ MANUAL（手动接口，FR-02），落库记录于 `trigger_source`；无 INIT（v1 无存量初始化——活跃集由周期扫描自然覆盖）
2. 调用百炼 Agent（非流式 `Application.call`，超时对齐 `taskCallTimeout` 默认 120s）；Agent 按销售画像技能调用数据工具 1/2（工具 3 仅扫描路径使用，不在画像序列内）
3. **无冷启动门槛**（Q22，与 ops FR-08 相反）：数据稀少客户照常分析，技能在 `reading` 中声明"数据有限，结论仅供参考"——不跳过、不降级、不拒绝
4. 输出按固定 schema 强校验（见 04 §3）：枚举越界（leadQuality/intentHeat/followPriority）、必填缺失、markdown 代码块包裹、`reading`/`strategy` >300 字、`script` >500 字 → 校验失败
5. 校验失败自动重试 1 次（重试请求附加错误提示）；重试仍失败 → 记 `last_run_status=FAILED` + `last_run_error` 摘要，**丢弃产出，严禁宽松落库**（Q4/Q22）
6. **信息完整度规则计算**（Q13）：落库前由本服务按基准字段非空加权计算 `infoCompleteness`（0~100，取整），写入画像整包——**AI 输出不得含该字段，含则校验失败**；基准字段清单 v1 硬编码于本服务（见 FR-08）
7. 落库成功：记录 `model`、`input_token`、`output_token`、`skill_version`（对齐 ops 审计纪律，Q26 沿用）；v1 覆盖式——同客户已有画像则覆盖（upsert），不保留历史（Q21）
8. 单个客户同一时刻至多一个进行中的分析（行级原子抢占，见 04 §4 写路径），并发触发后者直接拒绝/跳过

## FR-02 手动触发分析

**需求**：销售在客户详情页（宿主业务系统）手动触发"立即分析"。

**验收标准**：
1. 接口幂等触发：客户不存在（MCP 侧查无）→ `NOT_FOUND "客户不存在"`；`analyze_state=RUNNING` → `PARAM_ERROR "分析进行中"`
2. **触发范围不限活跃集**（Q12）：任意绑定客户可触发（休眠客户恰是销售盘活对象）；MCP 侧查无该客户才拒绝
3. 成功触发即返回（异步执行，不等结果）；`trigger_source=MANUAL`；操作人不设专用字段——异步落库时以触发时捕获的 UserContext 快照回填 `upd_user`/`upd_name`（Q29，捕获-重建模式）
4. v1 无冷却期（Q6）：重复触发不被拦截，靠 RUNNING 态互斥兜底

## FR-03 定时扫描触发

**需求**：系统周期扫描活跃消费客户，批量触发分析（每 7 天一轮）。

**验收标准**（经单测固定 Clock 验证）：
1. 各实例 `@Scheduled` 固定延迟轮询（默认间隔可配；每 7 天执行一轮全量扫描的节律由内部调度状态控制，v1 以固定 cron 表达式实现如 `0 0 3 ? * MON`——凌晨低峰执行，具体时刻实现期定）；扫描调用数据工具 3（活跃消费客户清单）获取**近 7 天有消费的客户**，不对全量客户逐个拉取数据
2. 命中客户跳过 `analyze_state=RUNNING` 者，逐一入队分析（`trigger_source=SCAN`）
3. 分析执行提交独立线程池（core 2 / max 4，对齐 scheduled-task 模式）；池满记日志放弃本轮该客户（下轮扫描自然重试）
4. 多实例同时扫描同一客户：行级原子抢占，至多一个实例执行分析（Q24）
5. 扫描自身失败（工具 3 调用异常）记 error 日志，不中断下轮扫描
6. **无扫描规则引擎**：不引入 ops 的 5 条预警规则——命中条件单一（近 7 天消费），无需可配置规则

## FR-04 画像查询（单客户，详情页数据源）

**需求**：宿主详情页查询指定客户的当前画像 + 实时基础数据。

**验收标准**：
1. **画像部分**：无画像 → `data.profile=null`（不报错，Q14-①：无旧画像展示"暂无 AI 分析"+ 触发入口由宿主渲染）；有画像 → 返回画像全量字段（schema 见 04 §3）
2. **实时基础数据部分**（Q14-②A）：响应聚合数据工具 1（CRM 基础信息+填报）与工具 2（行为日志）的实时结果——Header/Meta/经验预算/品类/活跃轨迹五个非 AI 模块的数据源；MCP 查无客户 → `NOT_FOUND "客户不存在"`
3. 响应含分析元数据：`analyzeTime`、`triggerSource`、`model`、`inputToken`、`outputToken`、`skillVersion`
4. **平台级可见**（Q9）：任何登录用户可查任何客户（不校验 `crt_user` 归属）
5. 有旧画像即返回旧画像 + 生成时间（覆盖式存储下天然如此）；前端据 `analyzeTime` 自行呈现新旧

## FR-05 画像筛选列表

**需求**：宿主列表页按评分条件批量定位跟进对象。

**验收标准**：
1. 筛选参数（全部可选，多条件 AND）：`leadQuality` / `intentHeat` / `followPriority` / `infoCompleteness`（Q7 四键）
2. 分页 `page`（默认 1）/ `size`（默认 20，上限 50），默认排序 `follow_priority` 升序（P0 在前）+ `generated_time` 降序（Q24）
3. 列表项：`customerId`、四评分键、`reading`、`generatedTime`、`bindingState`
4. 空结果返回 `total=0, data=[]` 而非错误
5. 平台级可见（同 FR-04）
6. **列表基座范围**：仅返回已有画像的客户（画像表驱动）；无画像客户不在列表（宿主如需全客户列表走 CRM 自有能力，本模块不背书）

## FR-06 话术输出与合规约束

**需求**：把话术类产出的合规规则固化为可测试约束（Q11/Q18）。

**验收标准**：
1. `script` ≤500 字中文，为可直接复制的完整话术（无 markdown 包裹、无前后缀说明文字）
2. skill 硬约束（镜像可查）：禁止承诺具体价格、收益数字、时效；**禁止虚构客户未表现出的意向信号**（如客户无广告消耗却说"注意到您加大投放"）
3. `reading` ≤300 字、`strategy` ≤300 字；三者均必填
4. v1 无人工审核流：约束靠 skill + 验收抽检（见 05 §4 验收 5）兜底；出现合规事故再升级审核流（v2 议题）

## FR-07 销售画像技能镜像维护（工程纪律）

**需求**：skill 文本变更可追溯（Q16，照搬 ops FR-09 模式）。

**验收标准**：
1. `designs/customer-profile/sales/sales-skill.md` 为单一事实源；内容含：数据工具调用策略（工具 1/2 序列）、三项评分判定标准、输出 schema 说明、话术合规硬约束（FR-06.2）、数据稀少声明指引（FR-01.3）
2. 任何 skill 文本变更必须走 PR review；同步到百炼为手动操作，PR 描述注明"已同步/待同步"
3. 本服务不加载、不解析该文件（运行时百炼侧生效）；镜像仅作资产版本管理
4. 画像落库记录 `skill_version`：取应用配置 `profile.sales.skill-version`（镜像同步百炼时随 PR 一并更新该配置）

## FR-08 信息完整度基准字段（显式规则）

**需求**：把"完整度怎么算"固化为可测试规则（Q13 落地，即 PRD 开放问题 8）。

**验收标准**：
1. 基准字段清单 v1 硬编码于本服务（清单与权重随 requirements 定稿冻结，调整走 PR）：
   | 字段 | 来源 | 权重 |
   |---|---|---|
   | 主营品类 | 工具 1 用户填报 | 15 |
   | 国家 | 工具 1 CRM 基础信息 | 10 |
   | 注册渠道 | 工具 1 CRM 基础信息 | 10 |
   | 客户等级 | 工具 1 CRM 基础信息 | 10 |
   | 激活状态 | 工具 1 CRM 基础信息 | 10 |
   | 最近订单数量（近 90 天） | 工具 1 消费统计（r3 设计驱动，待 03 §3 契约定稿） | 15 |
   | 消费金额 | 工具 1 消费统计（r3 设计驱动，待 03 §3 契约定稿） | 15 |
   | 工单数量 | 工具 1 消费统计（r3 设计驱动，待 03 §3 契约定稿） | 15 |
   > **弃用注记（r3）**：原清单含 DS 经验/周广告预算/细分市场三填报字段（各 15）——随设计终稿（ia.md v1.2）基础画像表不再展示而弃用，腾出的 45 权重由消费统计三字段（订单/金额/工单）承接；若 03 §3 契约定稿后消费字段不可得，权重回收至 CRM 基础信息字段（定稿时冻结）
2. 计算：已填字段权重合计 / 100 × 100%，取整；**规则运行于本服务**（非 AI、非 MCP）——AI 输出含 `infoCompleteness` 字段即校验失败（FR-01.6）
3. 边界断言（单测）：全空 = 0；全满 = 100；权重和恒等于 100（弃用三字段后仍为 100）
4. `infoCompleteness` 写入画像整包（`profile_json`）并投影为检索列 `info_completeness`（04 §1）
