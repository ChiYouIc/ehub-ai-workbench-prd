# 05 非功能需求与风险 — 销售转化画像模块

> 模块：customer-profile-sales（销售转化画像，**客户画像一期基础版本**） ｜ 关联 PRD 母本：`plans/customer-profile/sales/customer-profile-sales-prd.md`（v1.3 已定版） ｜ 状态：随定版生效（2026-08-26 roadmap 修订）
>
> 编号规则：`NFR-xx` 非功能需求 / `R-xx` 风险，模块内递增不复用。

## 1. 非功能需求（NFR）

### NFR-01 可见性与合规
- 画像为**平台级数据**（Q9）：任何登录用户可查任何客户画像（不校验 `crt_user` 归属）；手动触发操作人不设专用字段——由通用审计字段 `upd_user`/`upd_name` 承载（Q29，异步落库以 UserContext 快照回填）
- **PII 不进链路**（Q5 沿用）：数据工具出入参只含平台 ID 与统计形态数据；**邮箱不在本模块任何工具出入参中**（03 §3 通用约定），Header 邮箱展示归宿主 CRM 自有接口；本服务校验兜底（发现 PII 形态字段即记 error 并跳过）
- 接口认证机制见 [`../../auth/01-接口认证.md`](../../auth/01-接口认证.md)，本模块不重复定义

### NFR-02 性能与资源上限
- 扫描每 7 天一轮（v1 cron 固定，低峰执行）；扫描经工具 3 预取活跃清单，**绝不全量逐客户拉数据**（Q5）
- 分析执行线程池 core 2 / max 4（对齐 scheduled-task 模式）：池满记日志放弃该客户本轮（下轮扫描自然重试）
- 单次分析超时 `taskCallTimeout` 默认 120s（非流式 `Application.call`）；两轮工具调用的总耗时由该超时统一兜底
- 详情页聚合接口（GET /{customerId}）实时调工具 1/2（Q14-②A）——响应时间受 MCP 侧约束，联调期与 MCP 团队定基线（对齐 ops R-05 的 SLA 议题）

### NFR-03 可靠性（多实例与恢复）
- 多实例互斥**不依赖外部组件**：`analyze_state` 行级原子抢占（守卫 `IDLE` 或僵死超时），影响行数 0 即放弃——复用 scheduled-task 已验证模式（Q24）
- 实例被杀留 `RUNNING` 残留：超 30 分钟（沿用 `runningStaleMinutes` 模式，可配）任意实例轮询带守卫复位，**不补跑**（下轮扫描自然覆盖活跃客户）
- 画像落库严格 upsert：唯一约束 `uk_customer` 防并发重复；校验失败不污染已有画像（Q4 严禁宽松落库）

### NFR-04 可观测性
- 关键路径日志：扫描开始/结束（命中数/跳过数）、抢占结果、分析开始/结束（customerId/trigger_source）、校验失败与重试、僵死复位——均带 customerId
- 成本可归因：每行画像带 `model/input_token/output_token`；v1 无冷却期（Q6）的观测期成本波动靠该记录观测
- token 缺失（百炼响应未带）记 0，不视为失败

### NFR-05 可测试性
- 时间源注入 `Clock`（对齐 scheduled-task / ops）；完整度计算（FR-08）为纯函数可独立单测（全空/全满/权重和断言）
- MCP 数据工具以接口抽象 + 假实现测试（不依赖真实下游）；百炼调用以录制响应/桩测试，校验器与重试逻辑完全离线可测
- **接口 mock 先行**（r2/Q28 联调依赖）：03 §2 三接口的 mock 契约随开发启动同步交付宿主方

### NFR-06 契约纪律
- 数据工具契约（03 §3）为对 MCP 服务的**依赖声明**：工具随本需求同步开发（Q2），参数命名/错误结构定稿后的任何调整必须回写 03，双向同步
- 销售画像技能镜像 `designs/customer-profile/sales/sales-skill.md` 变更走 PR review（FR-07）；与百炼侧的手动同步状态在 PR 描述注明
- 画像卡片设计规范（`designs/customer-profile/sales/`）为对宿主业务系统的**交付契约**：卡片信息架构变更须同步该规范

## 2. 风险（R）

### R-01 三项评分全 AI 判断，一致性依赖 skill 质量（中）
leadQuality/intentHeat/followPriority 无确定性规则兜底（Q13 修订后完整度已剥离）；skill 迭代可能造成同一客户前后评分漂移；无冷却期（Q6）加剧重分析漂移可观察性。
**缓解**：人工抽检（验收 2）覆盖评分一致性；skill 版本化（Q16）使漂移可追溯；观测"同客户重分析评分变动率"，超阈值排查 skill 变更。

### R-02 话术合规依赖 skill 约束（中）
AI 话术可能作出价格/收益/时效承诺或虚构意向信号（Q11/Q18）；v1 无人工审核流。
**缓解**：skill 硬约束（FR-06.2）+ 验收 5 抽检兑底；出现合规事故即触发 v2 审核流议题；产出版本追溯由镜像 git 历史 + PR review 承担（FR-07.4 作废后口径）。

### R-03 下游 3 工具随本需求同步开发（高）
MCP 服务虽有但工具未完善（Q2）——进度耦合：工具延期直接阻塞联调与验收；契约初稿（03 §3）未经下游确认。
**缓解**：契约定稿会议尽早启动（开发顺序第一位）；本服务以接口抽象 + 假实现并行开发不受阻；验收 1（覆盖率）口径在工具真实性能明确后复核。

### R-04 前端宿主在业务系统侧，联调节奏外部依赖（中）
r2/Q28 后页面由宿主业务系统实现——接口契约理解偏差、联调排期、上线节奏均依赖宿主团队。
**缓解**：接口 mock 先行（NFR-05）供宿主并行开发；画像卡片设计规范（信息架构+草图）作为交付契约明确模块边界；联调窗口与宿主方提前锁定。

### R-05 无冷却期的成本波动（低）
Q6 显式决策：v1 手动刷新不限频；扫描每 7 天一轮批量分析活跃集，客户量大时单轮 token 总量可观。
**缓解**：RUNNING 态互斥天然限流并发；token 全量记录可核算单轮成本；扫描轮次固定（7 天）批量成本可预测；v2 视成本数据再议冷却与扫描频率。

### R-06 详情页实时聚合的性能与可用性（中）
详情接口实时调工具 1/2（Q14-②A），MCP 慢或不可用时详情页基础区不可用。
**缓解**：画像部分与基础数据部分独立返回（画像从库取，不受 MCP 影响）；MCP 侧失败时基础区降级为空对象+错误标记（不拖垮整页）；SLA 与重试口径列入契约定稿议题。

### R-07 覆盖式存储不可复盘（低）
v1 只留最新画像（Q21），无法回看历史判断。
**缓解**：v1 接受（显式决策，对齐 ops R-07）；v2 全量保留解决。

### R-08 完整度基准字段与权重的主观性（低）
FR-08 权重表（15/15/15/15/10/10/10/10）为初判，可能与销售实际认知有偏差。
**缓解**：清单与权重随 requirements 定稿冻结、调整走 PR 可追溯；完整度仅作参考性筛选键（非优先级决定因素）；观测使用率，v2 校准。

## 4. 验收标准（Q20，5 条）

1. 定时扫描命中客户（近 7 天有消费）画像覆盖率 ≥95%（成功落库口径；R-03 工具性能明确后复核口径）
2. 人工抽检 50 客户 `leadQuality`/`followPriority` 与资深销售判断一致率 ≥80%（覆盖 R-01 评分一致性）
3. **接口**四筛选键可用（质量/热度/优先级/完整度，03 §2 list 接口）——页面侧验收归宿主方（r2/Q28 口径调整）
4. token 消耗全量记录（每条画像含 model/input_token/output_token）
5. 话术抽检零硬承诺（价格/收益数字/时效）+ 零虚构意向信号（覆盖 R-02）
