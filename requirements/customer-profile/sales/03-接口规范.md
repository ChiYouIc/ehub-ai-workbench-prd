# 03 接口规范 — 销售转化画像模块

> 模块：customer-profile-sales（销售转化画像，**客户画像一期基础版本**） ｜ 关联 PRD 母本：`plans/customer-profile/sales/customer-profile-sales-prd.md`（v1.3 已定版） ｜ 状态：随定版生效（2026-08-26 roadmap 修订）
>
> 全部接口走统一响应包装（`ResponseType` 免二次包装）。**接口认证遵循全工程统一约定**（见 [`../../auth/01-接口认证.md`](../../auth/01-接口认证.md)）。错误码复用既有 `PARAM_ERROR / NOT_FOUND`，不新增。
>
> **可见性口径（Q9）**：画像为平台级数据，接口不校验 `crt_user` 归属——任何登录用户可查任何客户画像。
>
> **消费方说明（r2/Q28）**：页面由宿主业务系统（CRM 前端）承载，本组接口是宿主前端的直接数据源；建议实现期先出 mock 供宿主侧并行开发。

## 1. 前缀

`/profile/sales`（客户画像域内销售子域，与 ops 的 `/profile` 区分）。

## 2. 对外 REST 接口

### POST /profile/sales/{customerId}/analyze

| 项 | 值 |
|---|---|
| 完整路径 | `/ai-workbench/profile/sales/{customerId}/analyze` |
| 说明 | 手动触发指定客户立即分析（异步，不等结果；FR-02） |

**响应**：成功 → 统一成功响应。客户不存在（MCP 侧查无）→ `NOT_FOUND "客户不存在"`；`analyze_state=RUNNING` → `PARAM_ERROR "分析进行中"`。

**语义**：异步执行；`trigger_source=MANUAL`；操作人由 `upd_user`/`upd_name` 承载（Q29，不设专用字段）；**触发范围不限活跃集**（任意绑定客户可触发，Q12）；v1 无冷却期，靠 RUNNING 态互斥。

### POST /profile/sales/analyze/batch

| 项 | 值 |
|---|---|
| 完整路径 | `/ai-workbench/profile/sales/analyze/batch` |
| 说明 | 批量触发分析（实现期新增，2026-08-26；列表页多选后批量「AI 分析」入口的数据源） |

**Body**：JSON 数组 `["customerId1", "customerId2", ...]`（不可为空数组，否则 `PARAM_ERROR`）。

**响应**：`BatchAnalyzeResultVO`——`accepted`（成功受理数）+ `skipped`（跳过明细数组，每项 `customerId` + `reason`：`NOT_FOUND`=客户不存在 / `RUNNING`=分析进行中）。

**语义**：逐个预检 + 抢占，**跳过行不报错**（与单接口的 NOT_FOUND/PARAM_ERROR 报错语义不同：批量语义为部分受理）；逐个语义与单接口一致（不限活跃集、无冷却期、异步执行、trigger_source=MANUAL）。

### GET /profile/sales/{customerId}

| 项 | 值 |
|---|---|
| 完整路径 | `/ai-workbench/profile/sales/{customerId}` |
| 说明 | 详情页聚合查询：画像 + 实时基础数据（FR-04） |

**响应**：`SalesProfileDetailVO`（字段见 §4）。MCP 查无客户 → `NOT_FOUND "客户不存在"`；客户存在但无画像 → `data.profile=null`（HTTP 200，宿主渲染空态 + 触发入口，Q14-①）。

### GET /profile/sales/list

| 项 | 值 |
|---|---|
| 完整路径 | `/ai-workbench/profile/sales/list` |
| 说明 | 按评分条件筛选画像列表（FR-05） |

**Query 参数**（全部可选，AND 组合）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `leadQuality` | string | HIGH/MEDIUM/LOW（高/中/低） |
| `intentHeat` | string | HOT/WARM/COLD（热/温/冷） |
| `followPriority` | string | P0/P1/P2/P3 |
| `infoCompletenessMin` / `infoCompletenessMax` | int | 完整度 0~100 **闭区间筛选，可单边**（仅 Min = ≥Min；关卡①复核 F-2 修订，原精确匹配+v2 范围口径作废） |
| `page` / `size` | int | 默认 1 / 20，size 上限 50 |

**响应**：`TablePageResponse<SalesProfileListItemVO>`（`{code,total,data}`），默认排序 `follow_priority` 升序 + `generated_time` 降序（Q24）；空结果 `total=0, data=[]`。

> 列表仅含已有画像客户（画像表驱动，FR-05.6）。

## 3. 下游数据工具契约（对 MCP 服务的依赖声明）

> 本节是 PRD 决策 3（Q2/Q17）的落地：3 个数据工具契约初稿。**此为对下游的契约要求文档，不是本服务接口**；服务已有、工具未完善，随本需求同步开发——正式定稿需与 MCP 服务团队逐工具对齐（参数命名/错误结构可能微调，调整须回写本文）。

### 通用约定

| 项 | 约定 |
|---|---|
| 标识 | `customerId`（平台客户 ID，字符串）；**PII 一律不出现在任何工具的出入参**（Q5 沿用 ops 口径） |
| 错误返回 | 结构化 JSON 错误体（非异常断流）：`{"error":{"code":"...","message":"..."}}`——供 Agent 按技能指引补救（对齐 ops Q32 语义） |
| 邮箱处理 | Header 模块的邮箱属 CRM 侧已有展示项，由宿主前端从 CRM 自有接口取用；本模块工具出入参**不含邮箱**（PII 纪律），画像卡片 Header 的邮箱展示归宿主侧 |
| 固定态 | 绑定状态/激活状态为固定值（分析对象均为已绑定、有消费客户）——仅透传展示，不作评分/话术差异化信号；命令口径：`--start`/`--end` 为 `yyyy-MM-dd`、单次窗口 ≤90 天 |

### 工具清单（逻辑命令组——非具名 MCP 工具）

> **实现口径（2026-08-26 定）**：MCP 服务暴露的是**命令执行器**（执行 HyperSKU CLI），不开发具名聚合工具。下表「工具 1/2/3」为本仓库的**逻辑命令组代号**（用于 FR/章节交叉引用），实际调用 = 调用方经执行器逐条执行对应命令后聚合；`get_customer_sales_info` / `get_customer_behavior` / `list_active_consumption_customers` 三个曾拟工具名**作废**。

| 代号 | 用途 | 底层命令（ehub skill 调用模式） | 聚合产出 |
|---|---|---|---|
| 工具 1（CRM+消费命令组） | 画像序列：CRM 基础 + 填报 + 消费统计 | `customer extends` + `customer detail` + `customer profile order count`（近 90 天窗口）+ `customer profile transaction count`（近 90 天窗口） | 国家（=注册区域）/注册天数（=注册时间推算）/注册渠道（=客户来源）/客户等级 + 填报（DS 经验/周广告预算）+ 消费统计（近 90 天订单数/成交额）；命令原生其余输出透传不裁剪；FR-08 基准字段来自本组（消费统计不入基准）。~~主营品类/细分市场~~（r6 移出）、~~工单数量~~（r6 移除） |
| 工具 2（行为命令组） | 画像序列：行为日志 | `customer detail` | 最近登录时间；累计登录次数暂无命令来源——v1 返回 null 待下游补齐 |
| 工具 3（扫描专用） | 仅扫描路径由本服务直接调用，不进 Agent 序列 | **无现成命令——待下游新增 CLI 命令**（近 N 天有消费客户清单） | 近 N 天存在消费记录的客户 ID 列表（分页或限量） |

### 调用方约定

- **画像序列**（技能规定）：按技能 §2 命令清单①~④串行执行（= 工具 1/2 逻辑组，`customer detail` 结果复用不重发）；工具 3 仅扫描路径由本服务直接调用
- **失败语义**（对齐 ops Q32）：单工具返回结构化错误 → Agent 按技能重试 1 次或跳过并在 `reading` 声明数据缺失；连续失败 2 次必跳过
- **轮次护栏**：百炼不暴露轮次计数，超时 120s 兜底；轮次约束写在技能内（软约束）

## 4. SalesProfileDetailVO 字段（对外响应）

### profile（画像部分，无画像时为 null）

| 字段 | 类型 | 说明 |
|---|---|---|
| `leadQuality` | string | HIGH/MEDIUM/LOW（AI，Q18） |
| `intentHeat` | string | HOT/WARM/COLD（AI，Q18） |
| `followPriority` | string | P0/P1/P2/P3（AI，Q18） |
| `infoCompleteness` | int | 0~100（本服务规则计算，Q13/FR-08；**非 AI 产出**） |
| `reading` | string | ≤300 字中文线索速读（AI） |
| `strategy` | string | ≤300 字中文转化策略（AI） |
| `script` | string | ≤500 字中文可复制话术（AI，合规约束见 FR-06） |
| `analyzeTime` | datetime | 本次分析时间 |
| `triggerSource` | string | SCAN/MANUAL |
| `model` | string | 分析所用模型标识 |
| `inputToken` / `outputToken` | int | token 用量（审计纪律） |

> `skillVersion` 已移除（2026-08-26 实现期决策：技能版本不在响应/存储中承载，FR-07.4 作废）。

### basic（实时基础数据部分，Q14-②A）

| 字段 | 类型 | 来源 | 卡片模块 |
|---|---|---|---|
| `country` / `registeredDays` / `channel` / `level` / `bindingState` | string/int | 工具 1 | Meta |
| `activationState` | string | 工具 1/2 | Header 徽章 / 活跃轨迹 |
| `dsExperience` / `weeklyAdBudget` | string | 工具 1（填报） | 基础画像表（r5 恢复；无数据为 null，宿主渲染「未提供」） |
| ~~`mainCategory` / `nicheMarket`~~ | string | 工具 1（填报） | **r6 移出**：v1 下游填报无法提供，不入工具 1 出参与 basic（v2 视下游能力回补） |
| `totalLogins` / `lastLoginTime` | int/datetime | 工具 2 | 活跃轨迹（`totalLogins` 暂无命令来源——v1 返回 null 待下游补齐；`lastLoginTime` 由 `customer detail` 提供） |

> Header 的邮箱+ID 归宿主 CRM 自有数据；Footer 的生成时间取 `profile.analyzeTime`。

### SalesProfileListItemVO（列表项）

`customerId`、`leadQuality`、`intentHeat`、`followPriority`、`infoCompleteness`、`reading`、`generatedTime`、`bindingState`。
