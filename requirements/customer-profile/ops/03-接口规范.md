# 03 接口规范 — 客户画像模块

> 模块：customer-profile（ops 运营画像） ｜ 关联 PRD 母本：`plans/customer-profile/customer-profile-prd.md`（v1.3 已定版） ｜ 状态：随定版生效
>
> 全部接口走统一响应包装（`ResponseType` 免二次包装）。**接口认证遵循全工程统一约定**（见 [`../auth/01-接口认证.md`](../auth/01-接口认证.md)）。错误码复用既有 `PARAM_ERROR / NOT_FOUND`，不新增。
>
> **可见性口径（Q25）**：画像为平台级数据，接口不校验 `crt_user` 归属——任何登录用户可查任何客户画像。

## 1. 前缀

`/profile`（区别于聊天 `/chat` 与任务 `/task`，客户画像独立资源域）。

## 2. 对外 REST 接口

### POST /profile/{customerId}/analyze

| 项 | 值 |
|---|---|
| 完整路径 | `/ai-workbench/profile/{customerId}/analyze` |
| 说明 | 手动触发指定客户立即分析（异步，不等结果；FR-02） |

**响应**：成功 → 统一成功响应。客户不存在（MCP 侧查无）→ `NOT_FOUND "客户不存在"`；`analyze_state=RUNNING` → `PARAM_ERROR "分析进行中"`。

**语义**：异步执行；`trigger_source=MANUAL`；记录操作审计（操作人/时间/客户）；冷启动客户走降级画像不拒绝；v1 无冷却期，靠 RUNNING 态互斥。

### GET /profile/{customerId}

| 项 | 值 |
|---|---|
| 完整路径 | `/ai-workbench/profile/{customerId}` |
| 说明 | 查询指定客户当前画像（FR-05） |

**响应**：`ProfileVO`（字段见 §4）。无画像 → `NOT_FOUND "画像不存在"`。

### GET /profile/list

| 项 | 值 |
|---|---|
| 完整路径 | `/ai-workbench/profile/list` |
| 说明 | 按标签条件筛选画像列表（FR-06） |

**Query 参数**（全部可选，AND 组合）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `valueTier` | string | T1/T2/T3/T4/T5 |
| `lifecycle` | string | NEW/GROWING/MATURE/DECLINING/DORMANT |
| `churnRiskLevel` | string | HIGH/MEDIUM/LOW |
| `suggestedAction` | string | INTERVENE/INCENTIVE/OBSERVE/NONE |
| `trait` | string | 8 枚举之一（单值筛选；多值 v2） |
| `page` / `size` | int | 默认 1 / 20，size 上限 50 |

**响应**：`TablePageResponse<ProfileListItemVO>`（`{code,total,data}`），按 `analyze_time` 降序；空结果 `total=0, data=[]`。

### GET /profile/baseline

| 项 | 值 |
|---|---|
| 完整路径 | `/ai-workbench/profile/baseline` |
| 说明 | 当前平台基线值透传查询（FR-07，诊断用） |

**响应**：统一成功响应，data 为数据工具 6 的透传结果（基线指标集 + 刷新时间）。

## 3. 下游数据工具契约（对 MCP 统计服务的依赖声明）

> 本节是 PRD 开放问题 4 的落地：7 个数据工具的输入输出契约初稿。**此为对下游的契约要求文档，不是本服务接口**；正式定稿需与 MCP 服务团队逐工具对齐（参数命名/错误结构可能微调，调整须回写本文）。

### 通用约定

| 项 | 约定 |
|---|---|
| 标识 | `customerId`（平台客户 ID，字符串）；**PII 一律不出现在任何工具的出入参**（Q5） |
| 时间窗口 | 参数 `window`，枚举 `30d/90d/180d/365d`，**上限 365d**（Q34 契约级约束）；不传默认 `90d` |
| 错误返回 | 结构化 JSON 错误体（非异常断流）：`{"error":{"code":"...","message":"..."}}`——供 Agent 按 skill 指引补救（Q32） |
| 存量事实 | 注册天数/绑定天数等**当下快照**类字段不受 window 限制 |

### 工具清单

| # | 工具名（暂定） | 入参 | 出参要点 |
|---|---|---|---|
| 1 | `get_customer_basic` | `customerId` | 注册天数、店铺数、店铺平台类型、绑定天数、客户国家、历史累计订单数、`gmvPercentile`（**可选**：v1 缺失，MCP 计划 v2 提供；缺失时 AI 按绝对档位判，Q38） |
| 2 | `get_order_metrics` | `customerId`, `window` | 订单量、GMV、客单价、环比（vs 前一等同窗口）、近 6 月趋势方向、活跃月数 |
| 3 | `get_category_distribution` | `customerId`, `window` | TOP5 品类及占比、价格带分布 |
| 4 | `get_fulfillment_metrics` | `customerId`, `window` | 平均采购周期、退款率、纠纷率、物流投诉率 |
| 5 | `get_fund_status` | `customerId` | 充值频率、余额水位、账期使用情况 |
| 6 | `get_platform_baseline` | —（无入参，可选 metric 维度） | 退款率基线、纠纷率基线等平台级指标 + 数据刷新时间 |
| 7 | `screen_customers_by_rule` | `ruleId`(R1~R5), 可选阈值参数；初始化模式：绝对 GMV 阈值 + 窗口 | 命中客户 ID 列表（分页或限量）；初始化用绝对 GMV 阈值筛选（r3；分位/排名筛选 v2 提供） |

### 调用方约定

- **画像序列**（画像技能规定）：工具 1→2→3→4→5→6 固定顺序（Q29）；工具 7 仅扫描/初始化路径由本服务直接调用，不进 Agent 序列
- **失败语义**（Q32）：单工具返回结构化错误 → Agent 按技能重试 1 次或跳过并在 summary 声明缺失；连续失败 2 次必跳过
- **轮次护栏**（Q31）：百炼不暴露轮次计数，本服务不做硬限；超时 120s 兜底；轮次约束写在画像技能内（软约束）

## 4. ProfileVO 字段（对外响应）

| 字段 | 类型 | 说明 |
|---|---|---|
| `customerId` | string | 平台客户 ID |
| `valueTier` | string | T1~T5（AI 经技能决策，Q22；v1 判定输入为绝对档位表，r3/Q37） |
| `lifecycle` | string | NEW/GROWING/MATURE/DECLINING/DORMANT |
| `churnRisk` | object | `{level: HIGH/MEDIUM/LOW, signals: string[]}`（signals 引用指标证据） |
| `topCategories` | array | `[{name, share}]`，share 为 0~1 小数 |
| `traits` | string[] | 8 枚举多选 |
| `suggestedAction` | string | INTERVENE/INCENTIVE/OBSERVE/NONE |
| `summary` | string | ≤200 字中文 |
| `analyzeTime` | datetime | 本次分析时间 |
| `triggerSource` | string | SCAN/MANUAL/INIT |
| `triggerRules` | string[] | 命中规则 ID（R1~R5，MANUAL/INIT 为空） |
| `model` | string | 分析所用模型标识 |
| `inputToken` / `outputToken` | int | token 用量（Q26） |

降级画像（冷启动 MANUAL）：`lifecycle=NEW`，`churnRisk={level:"LOW",signals:[]}`，`traits=[]`，`triggerRules=[]`，summary 为基础摘要。
