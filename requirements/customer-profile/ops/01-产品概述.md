# 01 产品概述 — 客户画像模块

> 模块：customer-profile（ops 运营画像） ｜ 关联 PRD 母本：`plans/customer-profile/customer-profile-prd.md`（v1.3 已定版） ｜ 状态：随定版生效
>
> 决策溯源：Q1–Q35（含 r2 修订），详见 `plans/customer-profile/customer-profile-interview.md`。术语以 `GLOSSARY.md` 客户画像领域一节为准。

## 1. 背景与问题

平台拥有 1 万~10 万绑定店铺的 B2B 代发客户（月单量几百~上千不等），但运营对客户缺乏系统化认知：

- 不知道谁高价值、谁在流失、谁在快速增长——客户分层与差异化服务完全靠人工经验，覆盖不了这个量级
- 客户异常（GMV 下滑、售后恶化、疑似流失）没有系统化发现机制，靠运营盯盘
- 新接手客户时缺乏快速认知手段

目标（Q1）：**提升用户转化、降低流失风险**——先做客户分层与流失预警（被动查询），准确率验证后再考虑主动干预。

## 2. 产品方案

在 `ehub-ai-workbench` 服务中新增**独立模块 `customer-profile`**，构建自动化客户画像流水线（Q20）：

- **数据获取（Q28）**：独立下游 MCP 统计服务提供约 7 个**按业务问题切分的数据工具**（带时间窗口参数，回溯上限 365 天，Q34）；统计口径归数据属主，本服务不拥有
- **分析编排（Q29/Q33）**：百炼 Agent 侧配置**画像技能**（固定必调序列 + 分析规则 + 输出结构）；skill 全文以本仓库镜像 `designs/customer-profile/ops/profiling-skill.md` 为单一事实源，PR review 后手动同步百炼
- **双触发（Q15）**：定时扫描按 5 条内置规则经数据工具 7 预筛命中客户（非全量、自动规避冷启动，Q12）；运营后台手动触发指定客户
- **产出（Q19）**：固定 schema 画像 JSON（价值分层/生命周期/流失风险/主营品类/经营特征/建议动作）+ ≤200 字中文摘要；强校验 + 失败重试 1 次（Q23），严禁宽松落库
- **存储（Q10/Q21）**：本服务新表，v1 覆盖式只留最新；平台级可见（Q25）
- **初始化（Q16，r3 修订）**：按绝对 GMV 阈值筛选先行（近 90 天 GMV ≥ skill 档位表 T2 下限；MCP 分位数能力 v2 提供，届时切回"前 20%"相对口径）

本模块仅覆盖后端接口与调度；前端（ehub-web）UI 另行安排。MCP 统计服务为独立下游服务，另行立项，本模块只定义其对上契约（见 03）。

## 3. 目标用户与角色

| 角色 | 说明 | 关注点 |
|---|---|---|
| 运营人员 | 内部登录用户（持有效 JWT） | 画像查询、筛选定位异常客户群、手动触发分析 |
| 系统管理者 | 内部登录用户 | token 成本归因、分析失败率 |
| 平台调度 | 本服务定时扫描（无人参与） | 规则命中发现、触发分析、多实例互斥 |
| 下游 MCP 统计服务 | 外部数据属主（另行立项） | 数据工具契约、统计口径、PII 脱敏 |

注意：画像的**分析对象**是平台画像客户（平台客户 ID），不是本系统业务用户；画像不服从 `crt_user` 归属隔离（Q25）。

## 4. 用户故事

1. 作为运营人员，我想查看指定客户的 AI 画像（价值分层、生命周期、流失风险、主营品类、经营特征、摘要），以便快速了解一个不熟悉的客户
2. 作为运营人员，我想按条件筛选客户列表（如 churnRisk=HIGH、valueTier=T1、lifecycle=DECLINING），以便批量定位需要干预的客户群体
3. 作为运营人员，我想让系统自动发现异常客户（GMV 大幅下滑、连续衰减、售后超标、疑似流失、快速增长），无需人工盯盘
4. 作为运营人员，我想在客户详情页手动触发"立即分析"，以便现场获取或刷新某个客户的画像
5. 作为运营人员，我想让冷启动客户（数据不足）得到降级画像而非误导性结论，以便正确看待新客户
6. 作为运营人员，我想让画像对全体内部用户可见（平台级共享），以便跨运营协作使用同一份客户认知
7. 作为系统管理者，我想让每次分析记录所用模型与 token 消耗，以便成本可归因、可观测

## 5. 术语

| 术语 | 定义 |
|---|---|
| 平台画像客户 | 已绑定店铺、进入画像覆盖范围的 B2B 代发客户，以平台客户 ID 标识（见 GLOSSARY） |
| 数据工具 | 下游 MCP 统计服务暴露的按业务问题切分的查询工具（7 个，带时间窗口参数，上限 365 天） |
| 画像技能 | 配置于百炼 Agent 侧的分析规则/输出结构/取数策略指令资产；本仓库镜像为单一事实源 |
| 指标包 | 逻辑概念：画像所需指标全集，由数据工具结果按画像技能序列拼装而成 |
| 画像 | 一次分析产出的固定 schema 标签集 + 中文摘要；v1 覆盖式只留最新 |
| 扫描规则 | 本服务内置的 5 条硬编码预警规则（Q17），经数据工具 7 预筛命中客户 |
| 冷启动客户 | 绑定时长 <60 天或历史累计订单 <30 单的客户（v1 硬编码口径）；扫描自动跳过，手动触发降级画像 |
| 降级画像 | 仅 `lifecycle=NEW` + 基础摘要、无趋势结论的画像输出形态（Q12） |
| 触发来源 | 三种：SCAN（扫描）/ MANUAL（手动）/ INIT（存量初始化） |
