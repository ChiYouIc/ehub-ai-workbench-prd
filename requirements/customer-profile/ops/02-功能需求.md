# 02 功能需求 — 客户画像模块

> 模块：customer-profile（ops 运营画像） ｜ 关联 PRD 母本：`plans/customer-profile/customer-profile-prd.md`（v1.3 已定版） ｜ 状态：随定版生效
>
> 编号规则：`FR-xx`，模块内递增不复用。验收标准描述**外部可观察行为**。错误码沿用既有 `PARAM_ERROR / NOT_FOUND`，不新增。

## FR-01 生成画像（核心流水线）

**需求**：对指定平台画像客户执行一次完整分析，产出画像落库。

**验收标准**：
1. 触发来源三种：SCAN（扫描命中，FR-03）/ MANUAL（手动接口，FR-02）/ INIT（存量初始化，FR-04），落库时记录于 `trigger_source`
2. 调用百炼 Agent（非流式 `Application.call`，超时对齐 `taskCallTimeout` 默认 120s）；Agent 按画像技能固定序列调用数据工具 1→6 拼装指标包（工具 7 仅扫描路径使用，不在画像序列内）
3. 冷启动客户判定（硬编码口径：绑定时长 <60 天 **或** 历史累计订单 <30 单）：MANUAL 触发时走**降级画像**——仅输出 `lifecycle=NEW` + 基础摘要，不得含趋势类结论（churnRisk 置 LOW、signals 为空、traits 不含增长/收缩类标签）；SCAN/INIT 触发时**直接跳过**不调百炼
4. 输出按固定 schema 强校验（schema 定义见 04 §3）：枚举越界、必填缺失、markdown 代码块包裹、summary >200 字、traits 非法值 → 校验失败
5. 校验失败自动重试 1 次（重试请求附加错误提示）；重试仍失败 → 记 `last_run_status=FAILED` + `last_run_error` 摘要，**丢弃产出，严禁宽松落库**
6. 落库成功：记录 `model`、`input_token`、`output_token`（对齐 `ai_conversation_content` 既有纪律，Q26）；v1 覆盖式——同客户已有画像则覆盖（upsert），不保留历史
7. 单个客户同一时刻至多一个进行中的分析（行级原子抢占，见 04 §4 写路径），并发触发后者直接跳过

## FR-02 手动触发分析

**需求**：运营人员在客户详情页手动触发"立即分析"。

**验收标准**：
1. 接口幂等触发：客户不存在（MCP 侧无此客户）→ `NOT_FOUND "客户不存在"`；`analyze_state=RUNNING` → `PARAM_ERROR "分析进行中"`
2. 成功触发即返回（异步执行，不等结果）；`trigger_source=MANUAL`，记录操作审计（操作人 id+name 快照、时间、客户 ID）
3. 冷启动客户按 FR-01.3 输出降级画像（不拒绝请求）
4. v1 无冷却期（Q24）：重复触发不被拦截，靠 RUNNING 态互斥兜底

## FR-03 定时扫描触发

**需求**：系统周期扫描，自动发现命中预警规则的客户并触发分析。

**验收标准**（经单测固定 Clock 验证）：
1. 各实例 `@Scheduled` 固定延迟轮询（默认 5 分钟，可配）；扫描调用数据工具 7（规则筛选客户列表）获取命中客户，**不对全量客户逐个拉取指标**
2. 5 条内置规则硬编码（Q17，不做配置化）：
   - R1：GMV 环比下滑 ≥30%（近 30 天 vs 前 30 天）
   - R2：订单量连续 3 个周环比衰减
   - R3：退款率或纠纷率超平台基线 2 倍（基线来自数据工具 6）
   - R4：历史活跃（月均 ≥50 单）且近 30 天 0 订单
   - R5：GMV 环比增长 ≥50%
3. 命中客户自动跳过冷启动客户与 `analyze_state=RUNNING` 者；逐一入队分析（`trigger_source=SCAN`），规则命中标记记录于画像 `trigger_rules`
4. 分析执行提交独立线程池（core 2 / max 4，对齐 scheduled-task 模式）；池满记日志放弃本轮该客户（下轮扫描自然重试）
5. 多实例同时扫描同一客户：行级原子抢占，至多一个实例执行分析
6. 扫描自身失败（工具 7 调用异常）记 error 日志，不中断下轮扫描

## FR-04 存量初始化

**需求**：上线时对存量客户按价值分层初始化画像（Q16）。

**验收标准**：
1. 初始化任务以 `trigger_source=INIT` 执行；范围 = 近 90 天 GMV ≥ 绝对阈值的客户（阈值 = skill 档位表 T2 下限，v1 硬编码；经数据工具 7 绝对 GMV 阈值筛选获取清单——r3：MCP 分位数/排名能力计划 v2 提供）
2. 逐客户串行或小批量执行（不压满线程池，避免与在线流量争抢）；冷启动客户跳过
3. 单客户失败不阻断整体：记 FAILED 后继续下一客户；初始化结束后输出汇总日志（成功/失败/跳过计数）
4. 初始化可重跑（幂等：覆盖式落库天然幂等）

## FR-05 画像查询（单客户）

**需求**：运营查看指定客户的当前画像。

**验收标准**：
1. 无画像 → `NOT_FOUND "画像不存在"`；有画像 → 返回画像全量字段（schema 见 04 §3）
2. 响应含分析元数据：`analyzeTime`、`triggerSource`、`triggerRules`、`model`、`inputToken`、`outputToken`
3. **平台级可见**：任何登录用户可查任何客户（不校验 `crt_user` 归属，Q25）

## FR-06 画像筛选列表

**需求**：运营按标签条件批量定位客户群体。

**验收标准**：
1. 筛选参数（全部可选，多条件 AND）：`valueTier` / `lifecycle` / `churnRiskLevel` / `suggestedAction` / `trait`
2. 分页 `page`（默认 1）/ `size`（默认 20，上限 50），按 `analyze_time` 降序
3. 列表项：`customerId`、画像标签字段、`summary`、`analyzeTime`、`churnRiskSignals`
4. 空结果返回 `total=0, data=[]` 而非错误
5. 平台级可见（同 FR-05）

## FR-07 平台基线获取（透传）

**需求**：为规则 R3 与运营参考提供当前平台基线值。

**验收标准**：
1. 透传调用数据工具 6，返回当前基线指标集（退款率基线、纠纷率基线等）与数据刷新时间
2. 供扫描任务内部使用；运营查询接口 v1 不强制（可作诊断入口，随实现细化）

## FR-08 冷启动口径与降级画像（显式规则）

**需求**：把"数据不足客户怎么处理"固化为可测试规则（Q12）。

**验收标准**：
1. 冷启动判定口径 v1 硬编码：绑定时长 <60 天 **或** 历史累计订单 <30 单（两值来自数据工具 1）
2. SCAN/INIT 路径：冷启动客户**不调百炼、不落库**，扫描日志记跳过
3. MANUAL 路径：正常调百炼，但画像技能收到"降级模式"标记，输出仅 NEW + 基础摘要（约束见 FR-01.3）
4. 降级画像同样过 schema 强校验（churnRisk.signals 必须为空数组、traits 只允许 NONE 相关空集）

## FR-09 画像技能镜像维护（工程纪律）

**需求**：skill 文本变更可追溯（Q33）。

**验收标准**：
1. `designs/customer-profile/ops/profiling-skill.md` 为单一事实源；内容含：固定必调序列、valueTier 判定标准、输出 schema 说明、失败指引（单工具连续失败 2 次跳过 + summary 声明缺失）
2. 任何 skill 文本变更必须走 PR review；同步到百炼为手动操作，PR 描述注明"已同步/待同步"
3. 本服务不加载、不解析该文件（运行时百炼侧生效）；镜像仅作资产版本管理
4. 画像落库记录 `skill_version`：取应用配置 `profile.skill-version`（镜像同步百炼时随 PR 一并更新该配置）——版本值由配置注入而非文件解析；输出 schema 演进后凭此追溯存量画像产自哪版技能
