# 05 非功能需求与风险 — 用户画像模块（新用户转化）

> 模块：customer-profile ｜ 关联 PRD 母本：[`plans/customer-profile/customer-profile-prd.md`](../../plans/customer-profile/customer-profile-prd.md)（v1.3 草案待审） ｜ 状态：**前置拆解稿**（PRD 终审定稿时复核）
>
> 编号规则：`NFR-xx` 非功能需求 / `R-xx` 风险，模块内递增不复用。

## 1. 非功能需求（NFR）

### NFR-01 数据隔离与归属
- v1 平台级可见（内部销售全体），不区分角色/线索归属（Q24）；画像以 `customer_id` 为归属键，无用户级私有隔离
- 接口认证机制见 [`../auth/01-接口认证.md`](../auth/01-接口认证.md)，本模块不重复定义

### NFR-02 安全与 PII 合规
- **终端消费者 PII 不进 AI 链路**：`username`/`nickname`/`first_name`/`chat_account`/`chat_account_type`/`reply_to_email` 原值不出参、不入 `profile_json`（决策 7/26）；客户标识仅 `customerId`
- 客户标识（用户名/昵称等）由宿主老系统渲染，本服务接口不返回也不接收 PII（决策 22）
- 接口为普通 JSON 短请求，认证处理与既有接口一致，无 SSE 式跨线程传递问题

### NFR-03 资源上限与成本
- v1 纯手动触发（无定时扫描/周期重扫/自动回填/批量，均 →v2），触发天然低频，无自动成本失控面
- 每次分析全量记录 `model` / `input_token` / `output_token`，成本可归因（决策 20）
- 无冷却期（Q11）：调试期依赖 token 观测 + 验收标准 5；稳定后 v2 再议冷却

### NFR-04 可靠性（触发与分析）
- 同客户同一时刻至多一次分析：`run_state` 单语句原子抢占，影响行数 0 即幂等拒绝（决策 10）
- 非流式 AI 调用**异步受理**：抢占成功即返回，进度经详情 `runState` 观察（※D-1）；调用超时/失败 → 自动重试 1 次，再失败即弃 + `run_failed=1` + `run_error=<失败原因摘要>`（决策 15）
- 失败即弃**严禁宽松落库**；已有旧画像不因新分析失败丢失（Q25）
- 出池判定与列表过滤共用同一消费状态口径（`customer detail`「是否有已支付订单」），避免"可触发但列表不可见"裂缝（风险 6）

### NFR-05 可观测性
- 关键路径记日志：触发抢占结果、分析开始/结束（含 customerId/model/token）、schema 校验失败摘要、重试、弃 + 失败标记
- 分析进度与结局可从详情接口直接观察（`runState` / `runFailed` / `runError` / `updTime`）

### NFR-06 可测试性
- 核心纯逻辑可脱离下游与 AI 单测：**schema 校验器**（枚举/字数/条数/阶段一致/虚构信号）与**完整度规则计算**（文案解析 + 加权）
- 触发语义（池资格校验 / 幂等 / 并发抢占）用测试替身（customer detail mock + Clock）覆盖，不需真实百炼
- 时间字段生成用注入 Clock，单测可固定（对齐 scheduled-task NFR-06）

## 2. 风险（R）

### R-01 意向证据薄，评分偏静态（中，已确认接受）
v1 无行为数据，`intentHeat` 证据仅问卷自报 + 渠道归因 + 最近登录——证据薄、偏静态（Q13 确认接受）。
**缓解**：skill 判定标准弥补（intentHeat 信号权重表）；行为日志数据工具 v2 补强（Q4）。

### R-02 三项评分全 AI 判断，一致性依赖 skill 质量（中）
评分一致性受 prompt/模型波动影响。
**缓解**：人工抽检 50 客户与资深销售判断一致率 ≥80%（验收标准 2）；skill 镜像与百炼侧配置经 PR review 维护。

### R-03 文案解析脆弱（中）
本服务消费 `customer detail` 文案形态出参，下游文案调整可能破坏解析。
**缓解**：解析口径锁定为**只识别空值标记（`-`/`--`）与布尔形态**，不解析枚举文案语义（※D-4）；契约定稿随 requirements/03 冻结，变更走契约评审。

### R-04 老系统检索接口能力待确认（中）
能否筛"注册未消费"、字段丰富度待确认——影响检索列表体验，**不影响本服务接口契约**（Q16）。
**缓解**：接口契约先定稿并提供 mock；宿主侧并行接入。

### R-05 宿主联调与上线节奏依赖（中）
前端宿主在业务系统侧，接口联调与上线节奏依赖宿主团队。
**缓解**：接口契约先定稿并提供 mock；卡片 ia 设计产物（`designs/customer-profile/`）作为宿主侧交付规范。

### R-06 出池口径一致性（中）
出池判定依赖下游消费状态口径——`has_order` 字段与支付流水的一致性归数据属主。
**缓解**：触发校验与列表过滤共用同一口径（NFR-04）；`out_of_pool` 惰性回写接受标记滞后（※D-6），避免列表不可见与可触发的裂缝。

### R-07 异步触发失败的用户感知（低）
异步受理下，分析失败用户无法在触发请求得到即时反馈。
**缓解**：详情 `runState` / `runFailed` / `runError` / 卡片「刷新」可见；失败原因随 `run_error` 落库，记日志可定位。
