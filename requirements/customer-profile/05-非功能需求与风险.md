# 05 非功能需求与风险 — 客户画像模块

> 模块：customer-profile ｜ 关联 PRD 母本：`plans/customer-profile-prd.md`（v1.3 已定版） ｜ 状态：随定版生效
>
> 编号规则：`NFR-xx` 非功能需求 / `R-xx` 风险，模块内递增不复用。

## 1. 非功能需求（NFR）

### NFR-01 可见性与合规
- 画像为**平台级数据**：任何登录用户可查任何客户画像（不校验 `crt_user` 归属，Q25）；手动触发记录操作审计（`trigger_user/trigger_name`）
- **PII 不进链路**（Q5）：数据工具出入参只含平台 ID 与统计形态数据；终端消费者个人信息不得出现——此为对 MCP 服务的契约要求，本服务校验兜底（发现 PII 形态字段即记 error 并跳过）
- 接口认证机制见 [`../auth/01-接口认证.md`](../auth/01-接口认证.md)，本模块不重复定义

### NFR-02 性能与资源上限
- 扫描周期默认 5 分钟（可配）；扫描经工具 7 预筛，**绝不全量逐客户拉指标**（Q15）
- 分析执行线程池 core 2 / max 4（对齐 scheduled-task 模式）：池满记日志放弃该客户本轮（下轮扫描自然重试）；初始化任务小批量执行不压满池
- 单次分析超时 `taskCallTimeout` 默认 120s（非流式 `Application.call`，沿用既有配置模式）；多轮工具调用的总耗时由该超时统一兜底（Q31：百炼不暴露轮次计数，无法按轮限流）

### NFR-03 可靠性（多实例与恢复）
- 多实例互斥**不依赖外部组件**：`analyze_state` 行级原子抢占（守卫 `IDLE` 或僵死超时），影响行数 0 即放弃——复用 scheduled-task 已验证模式（architecture §4）
- 实例被杀留 `RUNNING` 残留：超 30 分钟（沿用 `runningStaleMinutes` 模式，可配）任意实例轮询带守卫复位，**不补跑**
- 画像落库严格 upsert：唯一约束 `uk_customer` 防并发重复；校验失败不污染已有画像（标签字段不写，Q23 严禁宽松落库）

### NFR-04 可观测性
- 关键路径日志：扫描开始/结束（命中数/跳过数）、抢占结果、分析开始/结束（customerId/trigger_source）、校验失败与重试、僵死复位——均带 customerId
- 成本可归因（Q26）：每行画像带 `model/input_token/output_token`；上线初期配合无冷却期（Q24）的调优期，成本波动靠该记录观测
- token 缺失（百炼响应未带）记 0，不视为失败

### NFR-05 可测试性
- 时间源注入 `Clock`（对齐 scheduled-task）；冷启动口径、5 条规则阈值、基线倍数为纯函数，可独立单测
- MCP 数据工具以接口抽象 + 假实现测试（不依赖真实下游）；百炼调用以录制响应/桩测试，校验器与重试逻辑完全离线可测

### NFR-06 契约纪律
- 数据工具契约（03 §3）为对 MCP 服务的**依赖声明**：参数命名/错误结构定稿后的任何调整必须回写 03，双向同步
- 画像技能镜像 `designs/customer-profile/profiling-skill.md` 变更走 PR review（FR-09）；与百炼侧的手动同步状态在 PR 描述注明

## 2. 风险（R）

### R-01 valueTier 由 AI 判断，分层一致性依赖 skill 质量（中）
Q22 修订后分层无确定性规则兜底；skill 迭代可能造成同一客户前后分层漂移。
**缓解**：人工抽检（验收标准 2）必须覆盖分层一致性；skill 版本化（Q33）使每次漂移可追溯到变更；观测"同客户重分析 tier 变动率"。

### R-02 多轮工具调用的成本与延迟（中）
原子化工具（Q28）意味着单次画像 6+ 轮调用，token 含全部工具结果，单次成本高于单工具方案；轮次仅 skill 软约束（Q31）。
**缓解**：120s 超时兜底；token 记录观测实际消耗；skill 迭代收敛序列（如合并低价值工具）；v2 若成本失控可回退聚合工具形态。

### R-03 串行调用失败率乘法效应（中）
7 工具链即使单个 99% 可用，整链 ≈93%（Q32 分析）。
**缓解**：工具层结构化错误返回 + Agent 跳过降级（缺哪块不分析哪块 + summary 声明）；观测"数据缺失声明率"，超阈值排查下游。

### R-04 无冷却期的成本波动（低）
Q24 显式决策：上线初期频繁改 skill 需要自由重跑；扫描每 5 分钟可能反复触发同一异常客户。
**缓解**：RUNNING 态互斥天然限流同一时刻并发；token 记录可核算；稳定后 v2 启用 7 天冷却。

### R-05 下游 MCP 服务可用性（中）
画像全链路依赖 MCP 统计服务；其不可用时扫描与手动分析均失败。
**缓解**：失败仅记 `last_run_status=FAILED` 不影响既有画像可读；扫描失败不中断下轮；与 MCP 服务的 SLA 对齐列入契约定稿议题。

### R-06 画像误导（AI 幻觉编造未提供的结论）（中）
AI 可能对低置信数据输出确定性口吻（如对新客户编造趋势）。
**缓解**：冷启动降级画像硬约束（FR-08：无趋势字段）；schema 强校验 signals 必须引用指标证据；抽检验收（一致率 ≥80%）承担最终把关。

### R-07 覆盖式存储不可复盘（低）
v1 只留最新画像，无法回看"三个月前 AI 的判断"（Q21）。
**缓解**：v1 接受（显式决策）；prompt/skill 迭代对比依赖人工抽检；v2 全量保留 + 指标快照解决。

### R-08 绝对档位漂移（中）
v1 无 GMV 分位数，valueTier 与初始化均依赖绝对阈值（r3/Q36/Q37）；平台增长或季节波动会使 T1~T5 边界逐渐失真。
**缓解**：档位表集中于 skill 镜像单一事实源，调整走 PR review 可追溯；观测 T1/T2 客户占比漂移作为调档信号；v2 分位数上线切回相对分层后消除。

## 3. 已识别但 v1 不处理

- 画像历史版本与指标快照（v2，Q21）
- GMV 分位数与相对分层（v2，Q36：MCP 能力计划 v2；上线后 skill 切回"优先分位数、缺失走绝对档位"）
- 重复分析冷却期（v2，Q24）
- 高风险客户主动推送（钉钉等，v2，Q11——准确率验证后）
- 扫描阈值配置化（Q17：稳定运行 3 个月后再议）
- 对话式分析入口（v2，Q30：数据工具已为其铺路）
- trait 多值筛选、标签位图索引（性能不足时 v2 再议）

## 4. 验收标准（Q27，5 条）

1. 初始化覆盖：近 90 天 GMV ≥ T2 档位下限的客户 100% 有画像（r3 绝对口径；v2 分位数上线后切回前 20%）
2. 准确率：人工抽检 50 个客户，lifecycle 与 churnRisk 判断与资深运营一致率 ≥80%（须覆盖 valueTier 分层一致性，R-01）
3. 失败率：AI 输出校验失败（重试后仍失败）占比 <5%
4. 成本：单客户单次分析 token 成本有记录（v1 观测不设硬指标）
5. 冷启动客户：手动触发输出降级画像（仅 NEW + 基础摘要），扫描规则自动跳过
