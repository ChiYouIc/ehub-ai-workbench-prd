# 01 产品概述 — 用户画像模块（新用户转化）

> 模块：customer-profile ｜ 关联 PRD 母本：[`plans/customer-profile/customer-profile-prd.md`](../../plans/customer-profile/customer-profile-prd.md)（v1.3 草案待审） ｜ 状态：**前置拆解稿**——按用户指示在 PRD 定稿前产出，PRD 终审定稿时如有决策变动需同步复核

## 1. 背景与问题

销售团队面对大量**已注册但尚未消费**的新客户，缺乏系统化的转化认知：不知道谁值得优先跟进、意向处于什么阶段、该用什么样的话术推动他绑定店铺并完成首单。目前完全依赖销售个人经验逐个翻客户资料判断，效率低、标准不统一、跟进时机靠感觉。

已有能力没有覆盖这个场景：

- 老系统只有客户资料检索，没有转化视角的结构化分析
- AI 工作台已有即时对话与定时任务，但没有"按客户个体出画像"的分析产物
- 跟进优先级、话术准备完全依赖个人经验，无法沉淀为组织能力

## 2. 产品方案

在 `ehub-ai-workbench` 服务新增独立模块 `customer-profile`（用户画像），为每个注册未消费客户生成一张**结构化画像卡片**（评分面板 / 线索速读 / 转化策略 / 可复制话术），推动客户**绑定店铺 → 首单支付成功**：

- **数据获取**：复用下游既有 `customer detail` 脱敏接口（`customer` + `customer_extend` 两表合并，文案形态出参，含消费状态与脱敏布尔信号），下游无需新增开发；池发现权归老系统（复用其用户检索接口）
- **AI 分析**：百炼 Agent 非流式调用，按用户画像技能（skill，镜像 `designs/customer-profile/skill.md`）执行，输出固定 schema 画像 JSON；skill 按转化阶段硬分流（未绑店→促绑店 / 已绑店未首单→促首单）；`infoCompleteness` 由本服务规则计算，不入 AI 输出
- **触发**：v1 纯手动单个触发（老系统检索列表行内「生成画像」+ 画像卡片详情页「重新生成」）；触发时实时校验池资格（消费状态）与并发占用（行级抢占）；无定时扫描/周期重扫/自动回填（→v2）
- **失败语义**：固定 schema 强校验失败自动重试 1 次，再失败即弃并记失败状态，严禁宽松落库——无 FALLBACK 降级形态
- **存储**：表 `ai_customer_profile`——`profile_json` 整包（唯一事实源）+ 五投影列（lead_quality / intent_heat / follow_priority / info_completeness + 转化阶段）；覆盖式 upsert 只留最新
- **前端双列表架构**：① 老系统检索列表（找客户 + 行内触发生成）；② 本服务画像列表（仅已生成画像客户，服务端五筛选：质量/热度/优先级/完整度/转化阶段，默认排序 `follow_priority` 升序 + 生成时间降序）——销售日常工作队列
- **承载边界**：前端页面（检索列表接入 + 画像列表 + 详情卡片）由**宿主业务系统承载**，不挂钩 ehub-web；本模块仅交付后端接口与卡片信息架构规范（ia 设计产物落 `designs/customer-profile/`）

**画像域基线复用**（前置母本 `plans/scheduled-task-prd.md` 及画像域共同模式）：DB 行级原子抢占、token 审计纪律（model / input_token / output_token 全量记录）、覆盖式 upsert、强校验失败即弃。

## 3. 目标用户与角色

| 角色 | 说明 | 关注点 |
|---|---|---|
| 销售人员 | 内部销售全体（v1 平台级可见，不区分角色/线索归属） | 快速了解客户、决定跟进优先级、直接可用的话术 |
| 系统管理者 | 服务运维与成本归责方 | token 消耗可归因、失败可观测、PII 合规 |
| 宿主业务系统前端（协作方） | 老系统侧承载检索列表接入与画像页面 | 接口契约稳定、mock 先行、PII 由宿主渲染 |
| 下游 MCP 数据服务（协作方） | `customer detail` 脱敏接口提供方 | 文案形态出参约定（本拆解 03 §3 锁定）不单方变更 |
| 百炼 Agent（协作方） | skill 宿主，非流式 `Application.call` | skill 镜像与百炼侧配置一致（PR review 维护） |

## 4. 用户故事

1. 作为销售人员，我想在老系统检索列表中对注册未消费客户一键生成画像，以便快速获得该客户的转化分析
2. 作为销售人员，我想在画像详情页看到结构化画像卡片（评分/速读/策略/话术），以便快速了解客户并决定下一步跟进动作
3. 作为销售人员，我想按转化阶段筛选客户（未绑店 / 已绑店未首单），以便按阶段组织我的跟进工作队列
4. 作为销售人员，我想在画像列表按评分筛选/排序客户（质量/热度/优先级/完整度），以便批量定位高优先级跟进对象
5. 作为销售人员，我想复制 AI 生成的销售话术直接使用，减少话术准备时间
6. 作为销售人员，我想对已生成画像的客户重新生成画像（含数据变化后），以便获取最新分析
7. 作为销售人员，我想在客户已转化后仍能回看其画像卡片，以便复盘"为什么他能转化"
8. 作为系统管理者，我想让每次分析记录模型与 token 消耗（对齐 scheduled-task 既有审计纪律），以便成本可归因

## 5. 术语

| 术语 | 定义 |
|---|---|
| 画像（画像卡片） | 一条 `ai_customer_profile` 记录：`profile_json` 整包渲染的结构化卡片（评分面板 + 基础画像 + 速读 + 策略 + 话术 + Footer） |
| 池（注册未消费池） | 已注册且无已支付订单的客户集合；池发现权归老系统，本系统不做客户清单发现 |
| 入池 / 出池 | 入池=已注册且无已支付订单（不设注册天数窗口，绑店不作硬条件）；出池=首单支付成功（下单未付仍在池内，属催单场景） |
| 池资格校验 | 触发请求实时调 `customer detail` 取「是否有已支付订单」：已出池即拒绝触发 |
| 转化阶段 | 未绑店（NOT_BOUND）/ 已绑店未首单（BOUND_NO_ORDER），由实时绑店状态判定，不由 AI 猜（GLOSSARY 已收录） |
| 双列表架构 | 老系统检索列表（找客户+触发）+ 本服务画像列表（工作队列）（GLOSSARY 已收录） |
| 信息完整度 | `infoCompleteness` 0–100，本服务按五层基准规则计算（问卷五项/联系方式/基础档案/渠道归因/绑店），不入 AI 输出 |
| 文案形态出参 | `customer detail` 出参约定：枚举命中映射显文案、普通空值 `-` / 渠道空值 `--`、布尔「是/否」 |
| 抢占 | 单语句原子 UPDATE（守卫 `run_state='IDLE'`），多实例同时触发同一客户时恰一个成功 |
| 覆盖式 upsert | 同客户重新生成成功即覆盖旧画像（整包+投影列同步刷新），只留最新，历史版本 →v2 |
| 惰性回写 | 出池标记 `out_of_pool` 在触发校验/详情访问路径发现已出池时回写，列表据此过滤（※拆解决策，见 §6） |

## 6. 拆解决策清单（PRD 定稿复核点）

本拆解含 PRD 显式授权的细化项与工程补决策，PRD 终审定稿时逐项复核：

| # | 拆解决策 | 依据 |
|---|---|---|
| ※D-1 | 触发**异步受理**：抢占成功即返回，前端凭详情 `runState` + 卡片「刷新」观察进度 | PRD 决策 22 操作区含「刷新」；非流式 AI 调用秒级~分钟级，不宜同步等待 |
| ※D-2 | `scripts` 落库形态定为**字符串数组**（2–3 元素） | PRD 决策 14 授权 requirements/03 定；卡片话术区块逐条独立复制（决策 22） |
| ※D-3 | 完整度五层分值定稿：问卷五项 60（各 12）/ 联系方式 10 / 基础档案 10（姓名 4 + company 3 + country 3）/ 渠道归因 10 / 绑店 10 | PRD 决策 17 授权 requirements 定分值（PRD 锁字段集） |
| ※D-4 | 完整度解析**只识别空值标记（`-`/`--`）与布尔形态**，不解析枚举文案语义（非空即记已填） | PRD 决策 6/13 文案解析口径；防下游文案调整导致脆弱解析 |
| ※D-5 | API 参数与投影列用英文码（HIGH/HOT/P0/NOT_BOUND…），`profile_json` 整包保持 AI 中文枚举原文；映射只发生在「校验通过→落库」单点 | 避免中文枚举进 URL/DB 列，同时整包忠实 AI 输出 |
| ※D-6 | 列表"默认只显示池内客户"以 `out_of_pool` **惰性回写**实现（触发/详情路径发现出池即回写），接受标记滞后 | PRD 决策 3；避免分页列表实时批量调下游 |
| ※D-7 | 校验器加一条一致性规则：AI 输出的阶段标签须与服务端实时判定一致，不一致视为校验失败（进重试） | PRD 决策 15 阶段判定权威在实时数据 |
