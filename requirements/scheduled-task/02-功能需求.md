# 02 功能需求 — 定时任务模块

> 模块：scheduled-task ｜ 关联 PRD 母本：`plans/scheduled-task-prd.md`（v1.0 已定版） ｜ 状态：随定版生效
>
> 编号规则：`FR-xx`，模块内递增不复用。验收标准描述**外部可观察行为**。错误码沿用 `ErrorCodeEnum` 既有枚举（PARAM_ERROR / NOT_FOUND），不新增。

## FR-01 创建任务

**需求**：业务用户创建一个定时任务。

**验收标准**：
1. 请求体 `{name, prompt, cronExpression}`；`name` 非空白且 ≤100 字符，`prompt` 非空白且 ≤8000 字符（复用现有上限），否则 → `PARAM_ERROR`
2. `cronExpression` 仅接受 Spring 6 段 cron；用 `CronExpression.next()` 算相邻两个未来触发点，间隔 <5 分钟 → `PARAM_ERROR`（Q2/Q12）
3. 每用户任务数（含停用、不含已删）达到 `maxTasksPerUser`（默认 20）→ `PARAM_ERROR`（Q13）
4. 创建成功同步创建绑定会话组 `ai_conversation`（`type=SCHEDULED(6)`、name=任务名），任务记录 `conversation_id`
5. 新任务默认 `status=ENABLED`、`run_state=IDLE`，`next_fire_time` = cron 下一未来触发点；写入创建人 id+name 快照
6. 响应返回成功（含任务 id）

## FR-02 任务分页列表

**需求**：业务用户分页查看自己的任务列表。

**验收标准**：
1. 返回当前用户（`crt_user`）名下、未逻辑删除的任务，按 `crt_time` 降序
2. 列表项字段（每用户 ≤20 量级，返回全量）：`id/name/prompt/cronExpression/enabled/conversationId/nextFireTime/lastRunTime/lastRunStatus/lastRunError/crtTime`
3. 时间字段沿用 Long→String、日期序列化既有 Jackson 约定
4. 空列表返回 `total=0, data=[]` 而非错误
5. `page<1` 默认 1；`size>50` 截断为 50；`size` 非法值 → `PARAM_ERROR`

## FR-03 更新任务

**需求**：业务用户更新任务的名称/prompt/执行时间/启停状态。

**验收标准**：
1. 请求体 `{name, prompt, cronExpression, enabled}` **全量必填**，缺任一 → `PARAM_ERROR`（Q15）
2. 字段校验同 FR-01（name/prompt 长度、cron 合法性与 ≥5 分钟间隔）
3. cron 变更或 `enabled=true`（重新启用）→ 重算 `next_fire_time`；`enabled=false` → `next_fire_time` 置 null
4. **执行中任务的更新对当前执行无效**（本轮仍用旧 prompt），下一轮生效
5. 任务不存在 / 不属于当前用户 / 已删 → `NOT_FOUND "任务不存在"`

## FR-04 删除任务

**需求**：业务用户删除不再需要的任务。

**验收标准**：
1. 置 `is_del=1`（逻辑删除），返回成功响应
2. 正在执行的一轮**让它跑完**（产出照常落库）；已删任务不再被调度扫描
3. **绑定会话组及其内容保留**（审计/成本核算口径一致），仍可经会话内容接口访问
4. 任务不存在 / 不属于当前用户 / 已删 → `NOT_FOUND "任务不存在"`

## FR-05 手动立即执行

**需求**：业务用户手动触发一次任务执行（调试 prompt 用）。

**验收标准**：
1. 停用任务也可手动执行
2. 任务 `run_state=RUNNING`（执行中）时再触发 → `PARAM_ERROR "任务正在执行"`
3. 手动执行**不推进** `next_fire_time`（不影响原 cron 排程）
4. 产出落库 `params` 标记 `{"trigger":"MANUAL","taskId":<id>}`；返回成功（异步执行，不等结果）

## FR-06 任务详情

**需求**：业务用户查看单个任务全量信息。

**验收标准**：
1. 返回字段同 FR-02 列表项（含 `conversationId`——前端凭此跳转会话历史）
2. 任务不存在 / 不属于当前用户 / 已删 → `NOT_FOUND "任务不存在"`

## FR-07 到点自动执行（调度行为）

**需求**：启用中的任务在 cron 触发点自动执行。

**验收标准**（经单测固定 Clock 验证，非 HTTP 可观察）：
1. 调度轮询扫描 `enabled=1 AND is_del=0 AND next_fire_time <= DB NOW()`；到期比较以数据库时间为基准
2. 错过的多个触发点**合并为一次执行**；抢占成功即把 `next_fire_time` 推进为 cron 下一未来点
3. 多实例同时到期：同一任务**至多一个实例执行**（行级原子抢占，影响行数 0 即跳过）
4. `RUNNING` 超过 `runningStaleMinutes`（默认 30 分钟，可配）→ 任意实例轮询可复位为 IDLE（带 `RUNNING` 守卫，多实例至多一个复位成功），**不补跑**
5. 每次执行写 user/assistant 两行到绑定会话组（`params={"trigger":"CRON","taskId":id}`），以任务归属人快照身份落库
6. 成功 → `last_run_status=SUCCESS`；失败/超时（`taskCallTimeout` 默认 120s）→ `FAILED` + `last_run_error` 摘要（≤500），**不重试**
7. 执行线程池（core 2 / max 4）满 → 记日志、复位 IDLE、该次触发放弃（`next_fire_time` 已推进，接受跳过）

## FR-08 会话列表 type 过滤放开（顺带修正）

**需求**：修正 `GET /chat/conversations` 实现中硬编码 `type=CHAT` 的差距，对齐管理 PRD 原决策（Q18）。

**验收标准**：
1. `type` 作为可选查询参数：不传返回该用户全部类型（CHAT + SCHEDULED）；传则仅返回该类型
2. 行为与 `requirements/chat-conversation/03-接口规范.md` 中该接口定义一致（该文档本就如此定义，本项是实现差距修正）

## 3. 归属校验统一口径

不存在 / 不属于当前用户 / 已删，三种情形统一 `NOT_FOUND "任务不存在"`——不泄露他人任务存在性，延续 v1 数据隔离口径（Q8/Q21）。
