# 05 非功能需求与风险 — 定时任务模块

> 模块：scheduled-task ｜ 关联 PRD 母本：`plans/scheduled-task-prd.md`（v1.0 已定版） ｜ 状态：随定版生效
>
> 编号规则：`NFR-xx` 非功能需求 / `R-xx` 风险，模块内递增不复用。

## 1. 非功能需求（NFR）

### NFR-01 数据隔离
- 任务归属校验以 `ai_scheduled_task.crt_user` 为隔离键；不存在 / 非本人 / 已删统一报 `NOT_FOUND "任务不存在"`（不泄露他人任务存在性，延续 v1 口径）
- 定时触发线程无 `UserContext`：以任务记录的**创建人 id+name 快照**作为本轮 user/assistant 内容行的落库身份（`crt_user`/`crt_name` 从任务行取），不依赖线程上下文
- 接口认证机制见 [`../auth/01-接口认证.md`](../auth/01-接口认证.md)，本模块不重复定义

### NFR-02 安全
- 任务六接口为普通 JSON 短请求，认证处理与既有接口一致，**不存在 SSE 式跨线程传递问题**
- 产出走既有内容落库路径，不向客户端泄露内部列（`tools/params/media_content`）

### NFR-03 性能与资源上限
- 每用户任务数 ≤20（`maxTasksPerUser`，默认 20）、cron 相邻触发 ≥5 分钟——两级限流防止调度与 token 成本失控
- 执行线程池 core 2 / max 4、队列 0：池满即放弃本轮（记 warn 日志 + 复位 IDLE），不排队堆积
- 调度轮询批量拉取有 batch 上限，扫描走 `idx_sched` 索引（`status+next_fire_time`），多实例重复扫描无害

### NFR-04 可靠性（多实例与恢复）
- 多实例互斥**不依赖外部组件**：单语句原子 UPDATE（守卫 `run_state='IDLE'`）抢占，影响行数 0 即放弃——无 Quartz / 分布式锁 / 独立调度中心（r2 定案）
- 实例被杀留下 `RUNNING` 残留：超 `runningStaleMinutes`（默认 30 分钟）由任意实例轮询带守卫复位为 IDLE，**不补跑**（错过即错过）
- 非流式调用超时 `taskCallTimeout`（默认 120s）：超时/失败只记录 `last_run_error`（≤500），**不重试**（避免重复产出污染会话）
- 到期判定用 DB `NOW()`（不受应用时钟偏差影响）；cron 下一触发点计算用注入 `Clock`（单测可控）

### NFR-05 可观测性
- 关键路径记日志：抢占结果、执行开始/结束（含 taskId/conversationId）、失败摘要、池满放弃、僵死复位——均带 taskId 便于追踪
- 每轮执行结局可从列表接口直接观察（`lastRunTime/lastRunStatus/lastRunError`）

### NFR-06 可测试性
- 时间源抽象：到期判定走 DB、cron 计算注入 `Clock`，单测可固定时间验证"到点执行 / 错过合并 / 僵死复位"
- 调度与执行解耦（抢占→提交线程池），执行逻辑可脱离 `@Scheduled` 独立单测

## 2. 风险（R）

### R-01 调度空窗（实例全部下线）（低）
轮询调度依赖至少一个存活实例；全部实例下线期间触发点静默错过，重启后合并为一次执行、不逐一补跑。
**决策**：接受（v1 明确不补跑）；若业务要求零丢失需引入持久化队列，v2 再议。

### R-02 执行超时与失败无重试（低）
网络抖动等偶发失败导致当轮 `FAILED`，用户需等下一触发点或手动执行。
**缓解**：`POST /task/{taskId}/run` 可即时补一次；失败摘要在列表可见，定位成本低。

### R-03 池满放弃（低）
并发执行超过线程池上限（max 4）时本轮触发被放弃，且 `next_fire_time` 已推进——该次执行实际跳过。
**缓解**：≥5 分钟触发间隔 + 每用户 20 任务上限使并发天然有限；记 warn 日志可观测。

### R-04 更新与执行竞态（低）
执行中收到更新：本轮用旧 prompt 跑完，下一轮用新配置。
**决策**：接受为 v1 已知语义（不做执行内一致性检查）；窗口短、后果仅一轮旧数据。

### R-05 删除与执行竞态（低）
删除时恰有执行进行中：本轮照常跑完、产出照常落库（会话组保留），之后不再调度。
**决策**：接受（内容永不物理删除，审计一致）。

### R-06 token 成本（中）
每任务每触发点一次完整模型调用，任务数×频次的调用量可能显著。
**缓解**：20 任务 + 5 分钟间隔两级上限封顶；每轮 token 用量随内容行落库，可核算。

## 3. 已识别但 v1 不处理

- 补跑 / 重试机制（错过即错过、失败不重试）
- 任务执行历史表（仅最近一轮三件套 + 会话内容行可追溯）
- 手动执行限流（依赖 20 任务上限间接约束）
- 动态扩缩调度线程池（参数可配，不改结构）

## 4. Out of Scope 汇总

- 前端 UI 实现（页面交互设计已另出：`designs/scheduled-task/scheduled-task-design.md` + `scheduled-task-pages.pen`，开发另行安排）
- 任务执行历史独立查询接口（用会话内容接口按 `conversationId` 回看）
- 补跑 / 重试 / 失败告警通知
- 任务级并发度配置、优先级、依赖编排
- 跨用户任务共享 / 管理员代管
- 流式输出到前端（定时执行天然无人在线观看，v1 非流式）
