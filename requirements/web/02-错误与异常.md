# 02 错误与异常 — 全工程通用约定

> 范围：全工程所有对外接口 ｜ 状态：已定版 ｜ 关联：`requirements/web/01-响应包装.md`、`GLOSSARY.md`
>
> 本文是全工程**错误码与异常体系的单一事实源**。描述对外可见的错误契约；实现规则见代码工程 `.agents/skills/web-conventions/`。

## 1. 错误码模型

- 错误码接口 `IErrorCode`：`code()` + `message()`
- 全局业务错误码 `ErrorCodeEnum`（实现 `IErrorCode`），分段如下：

| code 段 | 含义 | 现状枚举 |
|---|---|---|
| 0 | 成功 | `SUCCESS` |
| 1000~1002 | 认证 / 授权 | `UNAUTHORIZED`(1000)、`FORBIDDEN`(1002) |
| 2000~2003 | 请求 / 参数 | `BAD_REQUEST`(2000)、`PARAM_ERROR`(2001)、`NOT_FOUND`(2002)、`METHOD_NOT_ALLOWED`(2003) |
| 5000~5003 | 系统 | `INTERNAL_SERVER_ERROR`(5000)、`SERVICE_UNAVAILABLE`(5001)、`OPERATION_FAILED`(5003) |

- **现状缺口**：~~`PARAM_ERROR` 尚未定义~~（已补充 `PARAM_ERROR`(2001, "参数校验失败")，随会话组管理模块落地）

## 2. 异常体系

### ApiException（业务异常）— 预期内

- 构造：`new ApiException(IErrorCode)` 或 `new ApiException(IErrorCode, message)`
- 处理：`AbstractExceptionHandleAdvice.handleApiException` → `FailedResponse{code,message,time}`，**HTTP 状态统一 200**
- 语义：预期内的正常业务失败（如归属校验失败、参数校验失败），前端按 `code` 分支处理

### BaseException（基础异常）— HTTP 状态透传

- 抽象类，可携带 `HttpStatus`；处理：`handleBaseException` → `FailedResponse`，`code` 恒为 `OPERATION_FAILED`(5003)，HTTP 状态透传 `status()`

### 兜底

- `GlobalExceptionHandleAdvice`（`@ControllerAdvice`，order=100）：
  - `HttpClientErrorException` → 透传下游状态码 + `INTERNAL_SERVER_ERROR` code
  - `Exception` → `INTERNAL_SERVER_ERROR`(5000)，HTTP 500，`resetBuffer()` 清空半序列化数据

## 3. 断言工具 ApiAssert

- 统一业务校验入口：`ApiAssert.notNull/isNull/notEmpty/isEmpty/isTrue/isFalse/isEquals/notEquals/...`（均带 `IErrorCode` 参数，可带自定义 message）
- 校验失败抛 `ApiException`
- **开发规范**：业务参数/归属校验优先用 `ApiAssert`，不手写 `if throw`

## 4. 对外错误契约（摘要）

| 场景 | HTTP | body.code |
|---|---|---|
| 业务校验失败（参数、归属等） | 200 | 对应业务错误码（如 2002 `NOT_FOUND`） |
| 基础异常（状态透传） | 透传 | 5003 `OPERATION_FAILED` |
| 下游服务客户端错误 | 透传 | 5000 `INTERNAL_SERVER_ERROR` |
| 未捕获异常 | 500 | 5000 `INTERNAL_SERVER_ERROR` |
| 认证失败 | 认证层拦截 | 见 `requirements/auth/01-接口认证.md` |

## 5. 演进

- 新增错误码：先在 `ErrorCodeEnum` 对应段补充，再在本文错误码表登记；各模块文档只引用
- 新增异常类型：继承 `BaseException`（透传 HTTP 状态）或直接抛 `ApiException`（业务码）
