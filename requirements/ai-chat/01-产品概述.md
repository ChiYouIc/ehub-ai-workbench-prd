# 01 产品概述 — AI 对话模块

> 模块：ai-chat ｜ 关联 PRD 母本：`plans/ai-chat-sse-prd.md` (v1.0) ｜ 状态：已定版

## 1. 背景与问题

业务系统需要 AI 对话能力，但各业务前端不应直接对接百炼大模型平台：

- 直接对接需要每个前端管理百炼的 API Key、Agent AppId、SSE 协议细节，存在密钥泄露与重复开发成本
- 对话数据（会话组、对话内容、token 消耗）散落在百炼平台侧，公司无法留存、审计与分析
- 需要统一的用户身份体系（JWT）与对话数据权限隔离，百炼平台无法感知我们的用户

## 2. 产品方案

在 `ehub-ai-workbench` 服务中对百炼 Agent 做**二次封装**：

- 前端调用 `POST /chat/sse`（完整路径 `/ai-workbench/chat/sse`），服务端解析用户身份后，将请求封装为百炼 `ApplicationParam` 调用已发布的 Agent
- 通过百炼 `sessionId` 将同一会话组的消息在百炼侧串联（依赖 Agent 自带会话记忆），服务端同步保存会话组与对话内容
- 流式增量以 SSE `message` 事件推送；每轮对话结束后落库 user/assistant 两条消息及 token 用量

## 3. 目标用户与角色

| 角色 | 说明 | 关注点 |
|---|---|---|
| 业务用户 | 持有效 JWT 的终端用户，v1 唯一认证主体 | 流式体验、上下文续聊、数据隔离 |
| 前端开发者 | 各业务线前端 | 一个稳定 SSE 接口、清晰的事件协议 |
| 平台运营者 | 公司内部 | token 成本核算、对话审计 |

## 4. 用户故事

1. 作为业务用户，我想发起一次 AI 对话并流式看到 Agent 的回复，以便实时获取答案
2. 作为业务用户，我想在已有会话组中继续追问，以便 Agent 能结合上下文回答
3. 作为业务用户，我想让我名下的会话组/对话内容只有我自己可见，以保证数据隔离
4. 作为平台运营者，我想让每轮对话（含 token 消耗、所用模型）保存在我方数据库，以便成本核算与审计
5. 作为前端开发者，我想只对接一个稳定的 SSE 接口（无需感知百炼），以便降低接入成本
6. 作为业务用户，我想在我断开连接（关闭页面/取消）后，服务端停止继续拉取百炼输出，以便不浪费资源与 token

## 5. 范围

### v1 范围内
- 单个 SSE 对话接口 `POST /chat/sse`
- 会话组隐式创建与续聊
- 对话内容、token 用量全量落库（正常/断连/错误三种结局）
- 客户端断连后的资源回收

### v1 范围外（Out of Scope）
- 会话组列表/重命名/删除接口、历史消息查询接口
- 多 Agent/skill 分流、输入内容审核
- 百炼记忆体显式管理（`/api/v2/apps/memory/*`）、文件/多模态输入
- client token 服务间认证
- 流式中断后的「继续生成/重试」交互（断连只做资源回收，不续传）
