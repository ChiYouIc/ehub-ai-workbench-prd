# 02 功能需求 — AI 对话模块

> 模块：ai-chat ｜ 关联 PRD 母本：`plans/ai-chat-sse-prd.md` (v1.1) ｜ 状态：v1.1（2026-08-25，新增 FR-10~14）
>
> 编号规则：`FR-xx`，模块内递增不复用。验收标准描述**外部可观察行为**。

## FR-01 发起对话（流式回复）

**需求**：业务用户提交 `prompt` 发起对话，实时流式收到 Agent 回复。

**验收标准**：
1. 有效请求返回 `200` + `text/event-stream`，回复以 `message` 事件逐片推送（增量分片）
2. 正常结束推送 `end` 事件，data 含最终汇总 `{conversationId, models, inputToken, outputToken}`，随后关流
3. 首个 `message` 分片即携带 `conversationId`，前端可据此建立会话

## FR-02 会话组隐式创建

**需求**：首轮对话不传 `conversationId` 时自动创建会话组。

**验收标准**：
1. 新建会话组 `name` 默认取首条 `prompt`，`type` 默认 CHAT=0
2. 新建会话组在首轮调用百炼前先落库（即使百炼失败也留有会话组记录）
3. v1 不提供显式「创建会话组」接口

## FR-03 会话组续聊与归属校验

**需求**：传入 `conversationId` 在已有会话组中继续对话。

**验收标准**：
1. 会话组存在且 `crt_user` = 当前用户 → 续聊，透传该组的百炼 `sessionId`
2. 不存在**或**不属于当前用户 → 统一 `NOT_FOUND "会话不存在"`（不泄露他人会话存在性）

## FR-04 上下文记忆（依赖百炼 sessionId）

**需求**：多轮上下文由百炼 Agent 侧记忆维持。

**验收标准**：
1. 本服务不组装历史 messages、不调用百炼记忆体接口
2. 首次回复后从 Agent 响应取出 `sessionId` 回写会话组（仅首次，已有则不覆盖）

## FR-05 对话内容落库（正常轮次）

**需求**：每轮正常对话结束后保存完整记录。

**验收标准**：
1. 保存 user + assistant 两条 `ai_conversation_content`
2. assistant 记录 `models`（去重逗号连接）、`inputToken`、`outputToken`
3. token 统计缺失时记 0

## FR-06 中断轮次落库（客户端断连）

**需求**：客户端断连被取消的一轮，已产生数据不丢失。

**验收标准**：
1. user 消息 + 已收到的部分 assistant 文本落库
2. assistant `params` 存 `{"interrupted":true,"reason":"client_disconnected"}`

## FR-07 错误轮次落库（百炼失败/空回复）

**需求**：百炼调用失败或空回复的一轮可追溯。

**验收标准**：
1. user 消息 + assistant 错误占位落库，`params` 存 `{"error":true,"code":"<错误码>"}`
2. 空回复判断：流结束仍无任何文本分片
3. 前端收到 `error` 事件（data 含 `{code, message}`），随后关流

## FR-08 客户端断连回收

**需求**：客户端断开后服务端停止拉取百炼输出。

**验收标准**：
1. 注册 `SseEmitter` 的 `onCompletion/onTimeout/onError` 回调
2. 触发任一回调后取消百炼流订阅，不再有新分片被消费
3. 回收后按 FR-06 落库

## FR-09 入参校验

**需求**：流式开始前校验入参，非法请求快速失败。

**验收标准**：
1. `prompt` 空白或超过 8000 字符 → `PARAM_ERROR`（普通 JSON 错误，非 SSE）
2. `type` 不传默认 CHAT=0；传非 CHAT 值 → `PARAM_ERROR`
3. 校验发生在流式开始前，走统一异常包装

## FR-10 模型选择

**需求**：用户可在对话前选择模型，不同模型映射到不同百炼 Agent。

**验收标准**：
1. `GET /chat/models` 返回可用模型列表（id、名称、描述）
2. `POST /chat/sse` 请求体可选传 `modelId`；不传使用默认模型
3. 传无效 `modelId` → `PARAM_ERROR`
4. SSE 事件中 `models` 字段反映实际使用的模型

## FR-11 消息评价（赞/踩）

**需求**：用户可对单条 assistant 消息进行赞或踩评价。

**验收标准**：
1. `POST /chat/feedback` 请求体 `{contentId, feedback}`，`feedback` 枚举 `up`/`down`/`none`（取消评价）
2. 评价存入 `ai_conversation_content.params` 字段，JSON key 为 `feedback`
3. 接口校验：消息存在且 `crt_user` = 当前用户 → 写入；否则 → `NOT_FOUND`
4. 同一消息可重复评价，新值覆盖旧值

## FR-12 重新生成 / 错误重试

**需求**：用户可对已完成的助手回复重新生成（用新回答替换旧回答）；错误卡的重试语义等同。

**验收标准**：
1. `POST /chat/sse` 请求体可选传 `regenerateContentId`（long，指定要替换的 assistant 消息 ID）；传此字段时 `prompt` 可不传
2. 服务端取该 assistant 消息的上一条 user 消息的 `content` 作为 prompt，重新调用百炼
3. 百炼调用使用同一会话组的 `sessionId`（上下文保持）
4. 调用成功后：旧 assistant 消息 `is_del=1` 逻辑删除；新 user + assistant 消息落库（user 消息复用原始 prompt 文本）
5. `regenerateContentId` 不存在或不属于当前用户 → `NOT_FOUND`
6. 若该 assistant 消息上一条不是 user 消息（如连续 error） → `PARAM_ERROR`

## FR-13 @提及成员

**需求**：用户可在输入中 @提及同事，前端展示成员选择弹层。

**验收标准**：
1. `GET /chat/members?keyword=` 接口返回成员列表（id、name、title/职位），`keyword` 可选，模糊匹配姓名
2. 成员数据来源于组织架构/通讯录（v1 首期从钉钉通讯录接口拉取并缓存）
3. 选中成员后，`@成员名` 原样拼入 `prompt` 文本，随 `POST /chat/sse` 传给百炼
4. 服务端不做 @提及的特殊解析——百炼 Agent 自行理解语义
5. 弹层展示、过滤、键盘交互为纯前端行为，无后端参与

## FR-14 文件上传

**需求**：用户可上传文本文件作为对话输入的一部分。

**验收标准**：
1. `POST /chat/upload` 接口上传文件，限制 10MB，返回 `{fileId}`
2. 仅支持文本类文件后缀：`.txt` / `.csv` / `.json` / `.md`；其他后缀 → `PARAM_ERROR`
3. `POST /chat/sse` 请求体可选传 `fileIds`（long 数组）
4. 服务端读取文件内容，按 `[文件名]\n文件内容\n\n` 格式拼接到 prompt 前部，然后调百炼
5. 拼接后整体仍受 8000 字符上限约束（校验时计入文件内容长度）
6. 上传文件 v1 不持久化关联到对话内容表（v2 再做）
