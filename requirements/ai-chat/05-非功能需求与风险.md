# 05 非功能需求与风险 — AI 对话模块

> 模块：ai-chat ｜ 关联 PRD 母本：`plans/ai-chat-sse-prd.md` (v1.0) ｜ 状态：已定版
>
> 编号规则：`NFR-xx` 非功能需求 / `R-xx` 风险，模块内递增不复用。

## 1. 非功能需求（NFR）

### NFR-01 数据隔离
- 会话组归属校验以 `ai_conversation.crt_user` 为隔离键；不存在与无归属统一报 `NOT_FOUND "会话不存在"`
- 接口认证机制见 [`../auth/01-接口认证.md`](../auth/01-接口认证.md)；client token 服务间认证不在范围

### NFR-02 安全
- 百炼 API Key 仅存服务端配置（env 注入），任何响应不得回显
- 不泄露他人会话存在性；SSE 事件不含其他用户数据

### NFR-03 并发与线程模型
- SSE 长任务运行于独立线程池 `asyncThreadPool`(core=50, max=100)，与 HTTP 容器线程解耦
- UserContext 跨线程采用「主线程捕获-异步线程重建」；SSE 结束后需清理 ThreadLocal 防泄漏

### NFR-04 可靠性（落库完整性）
- 正常/中断/错误三种轮次结局**均落库**（Q12/Q13），无数据丢失
- 落库与推流解耦：落库失败不影响已推送内容，但需记日志（error 级）供对账

### NFR-05 可配置性
- 错误兜底文案、百炼 `app-key`/`app-id`、prompt 长度上限（默认 8000）为配置项（`WorkbenchProperties` + yaml）
- 移除硬编码 `:::agent-error`

### NFR-06 可观测性
- 百炼调用失败、空回复、断连回收、落库失败均记日志，关键路径含 `conversationId`/userId 便于追踪

## 2. 风险（R）

### R-01 百炼记忆依赖（高）
上下文完全依赖百炼 `sessionId`（Q5）。百炼侧记忆被清空/过期 → 历史上下文丢失，本系统无法恢复。
**缓解**：v2 评估服务端记忆组装（落库数据已具备完整历史）。

### R-02 SDK 阻塞式流（中）
`blockingForEach` 占用线程池线程直到流结束；长回复高峰期可能耗尽 `asyncThreadPool`(50/100) → 新对话排队。
**缓解**：监控线程池水位；必要时调参或改造为异步订阅（v2）。

### R-03 usage 统计缺失（中）
百炼 usage 返回缺失/为空时只能记 0（FR-05），成本核算偏低。
**缓解**：NFR-06 日志标记 usage 缺失轮次，定期与百炼控制台对账。

### R-04 断连检测时延（中）
SSE 断连依赖容器触发 `onError/onCompletion`，存在检测时延；时延内分片照常从百炼拉取（少量浪费）。
**缓解**：接受为 v1 已知限制；写入风险清单跟踪。

### R-05 token 统计口径（低）
`end` 汇总为各分片 usage 累加，与百炼控制台可能存在口径差异。
**缓解**：以 `end` 汇总为前端展示口径，成本核算以落库数据为准。

## 3. 已识别但 v1 不处理

- 高峰期落库排队延迟（异步线程池容量 50/100，见 NFR-04）
- 会话组无限增长（列表/删除接口在 Out of Scope）

## 4. Out of Scope 汇总

- 会话组列表/重命名/删除接口、历史消息查询接口
- 多 Agent/skill 分流、输入内容审核
- 百炼记忆体显式管理（`/api/v2/apps/memory/*`）、文件/多模态输入
- client token 服务间认证
- 流式中断后的「继续生成/重试」交互（断连只做资源回收，不续传）
