# 02 功能需求 — 模型配置管理

> 模块：model-config（admin 子模块）｜ 关联 PRD 母本：`plans/model-config-prd.md` (v1.0) ｜ 状态：已定版
>
> 编号规则：`FR-xx`，模块内递增不复用。验收标准描述**外部可观察行为**。

## Provider 管理

### FR-01 新增 Provider

**需求**：管理员新增一个第三方 Provider，填写名称、类型、baseUrl 和 API Key。

**验收标准**：
1. 请求体包含 `name`（必填）、`code`（必填，枚举校验）、`baseUrl`（必填，合法 URL）、`apiKey`（必填）、`authType`（必填，枚举校验）、`extraHeaders`（选填，合法 JSON 或 null）
2. `code` 仅接受预定义枚举：`OPENAI`、`DEEPSEEK`、`CLAUDE`、`CUSTOM`
3. `authType` 仅接受：`API_KEY`、`BEARER`、`NONE`
4. `apiKey` 入库前 AES 加密存储
5. `baseUrl` 校验为合法 HTTP/HTTPS URL
6. 新增成功返回完整 Provider 信息（apiKey 脱敏展示）
7. 操作日志打印（info 级，含操作人 userId、操作类型 `CREATE_PROVIDER`、Provider ID）

### FR-02 编辑 Provider

**需求**：管理员修改已有 Provider 的配置。

**验收标准**：
1. 可修改字段：`name`、`baseUrl`、`apiKey`、`authType`、`extraHeaders`；`code` 不可修改
2. `apiKey` 修改时重新加密存储；未修改则不更新
3. 不存在的 ID → `NOT_FOUND`
4. 已软删除的记录不可编辑 → `NOT_FOUND`
5. 操作日志打印（info 级，含操作人、操作类型 `UPDATE_PROVIDER`、Provider ID）

### FR-03 查询 Provider 列表

**需求**：获取所有 Provider 列表（全量，不分页）。

**验收标准**：
1. 返回所有未软删除的 Provider，按 `crt_time` 降序排列
2. 每条记录的 `apiKey` 脱敏展示（如 `sk-****abcd`）
3. 每条记录附带其下 Model 数量（`modelCount`）
4. 响应为空数组时返回 `[]`，不返回 null

### FR-04 查询 Provider 详情

**需求**：获取单个 Provider 的完整信息。

**验收标准**：
1. 按 ID 查询，返回完整 Provider 信息（apiKey 脱敏）
2. 不存在或已软删除 → `NOT_FOUND`

### FR-05 启用/禁用 Provider

**需求**：管理员切换 Provider 的启用状态。

**验收标准**：
1. `enabled` 字段在 0（禁用）和 1（启用）之间切换
2. **禁用阻断**：若该 Provider 下有 `enabled=1` 的 Model → 返回 `PARAM_ERROR "该 Provider 下存在启用中的模型，请先禁用相关模型"`
3. 不存在的 ID 或已软删除 → `NOT_FOUND`
4. 操作日志打印（info 级，含操作人、操作类型 `TOGGLE_PROVIDER`、Provider ID、新状态）

### FR-06 删除 Provider（软删除）

**需求**：管理员软删除一个 Provider。

**验收标准**：
1. 设置 `is_del=1`，不从数据库物理删除
2. **删除阻断**：若该 Provider 下有 `enabled=1` 的 Model → 返回 `PARAM_ERROR "该 Provider 下存在启用中的模型，请先禁用相关模型"`
3. 级联软删除：该 Provider 下所有 Model（无论启用/禁用）同时设置 `is_del=1`
4. 不存在的 ID 或已软删除 → `NOT_FOUND`
5. 操作日志打印（info 级，含操作人、操作类型 `DELETE_PROVIDER`、Provider ID、级联 Model 数量）

## Model 管理

### FR-07 新增 Model

**需求**：管理员在指定 Provider 下新增一个模型。

**验收标准**：
1. 请求体包含 `providerId`（必填）、`name`（必填）、`description`（选填）、`providerModelId`（必填，如 `gpt-4o`）、`sortWeight`（选填，默认 0）
2. `providerId` 必须指向一个存在的、未软删除的 Provider
3. 同一 Provider 下 `providerModelId` 不可重复 → `PARAM_ERROR "该 Provider 下已存在相同标识的模型"`
4. 新增成功返回完整 Model 信息
5. 操作日志打印（info 级，含操作人、操作类型 `CREATE_MODEL`、Model ID）

### FR-08 编辑 Model

**需求**：管理员修改已有 Model 的配置。

**验收标准**：
1. 可修改字段：`name`、`description`、`providerModelId`、`sortWeight`；`providerId` 不可修改
2. `providerModelId` 修改时需校验同 Provider 下唯一性
3. 不存在的 ID、已软删除 → `NOT_FOUND`
4. 操作日志打印（info 级，含操作人、操作类型 `UPDATE_MODEL`、Model ID）

### FR-09 查询 Model 列表

**需求**：获取指定 Provider 下的所有 Model 列表（全量，不分页）。

**验收标准**：
1. 按 `providerId` 过滤，仅返回该 Provider 下未软删除的 Model
2. 按 `sort_weight` 升序排列（权重相同则按 `crt_time` 升序）
3. `providerId` 不存在或已软删除 → 返回空数组 `[]`
4. 响应为空数组时返回 `[]`，不返回 null

### FR-10 查询 Model 详情

**需求**：获取单个 Model 的完整信息。

**验收标准**：
1. 按 ID 查询，返回完整 Model 信息（含所属 Provider 名称）
2. 不存在或已软删除 → `NOT_FOUND`

### FR-11 启用/禁用 Model

**需求**：管理员切换 Model 的启用状态。

**验收标准**：
1. `enabled` 字段在 0（禁用）和 1（启用）之间切换
2. 不存在的 ID 或已软删除 → `NOT_FOUND`
3. 操作日志打印（info 级，含操作人、操作类型 `TOGGLE_MODEL`、Model ID、新状态）

### FR-12 删除 Model（软删除）

**需求**：管理员软删除一个 Model。

**验收标准**：
1. 设置 `is_del=1`，不从数据库物理删除
2. 不存在的 ID 或已软删除 → `NOT_FOUND`
3. 操作日志打印（info 级，含操作人、操作类型 `DELETE_MODEL`、Model ID）
