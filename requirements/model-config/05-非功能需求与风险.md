# 05 非功能需求与风险 — 模型配置管理

> 模块：model-config（admin 子模块）｜ 关联 PRD 母本：`plans/model-config-prd.md` (v1.0) ｜ 状态：已定版
>
> 编号规则：`NFR-xx` 非功能需求 / `R-xx` 风险，模块内递增不复用。

## 1. 非功能需求（NFR）

### NFR-01 凭证安全
- API Key 以 AES 对称加密存储，主密钥通过环境变量注入（不落 yaml 仓库）
- 任何接口响应不回显明文，脱敏规则见接口规范 4.1
- 操作日志（含日志文件）不得出现 apiKey 明文

### NFR-02 权限控制
- 管理接口仅管理员可访问，认证遵循 [`../auth/01-接口认证.md`](../auth/01-接口认证.md)
- 权限校验在网关/拦截器层统一完成，业务代码不重复判断

### NFR-03 操作可追溯
- 标准审计字段（`crt_*` / `upd_*`）完整记录操作人与时间
- 所有写操作打印 info 级操作日志（格式见接口规范 4.2），供问题排查与审计对账

### NFR-04 数据一致性
- Provider 级联软删除与其下 Model 的软删除在同一事务内完成
- 唯一性校验（Provider code、Model providerModelId）在事务内先查后写，配合应用层唯一索引兜底

### NFR-05 管理界面可用性
- 管理接口为纯 CRUD，无长事务、无流式，响应时间要求 ≤500ms（P99）
- 列表全量返回，预期数据量 <100 条，无分页需求

### NFR-06 与百炼路径隔离
- 本模块所有表、接口、代码与百炼调用链（`POST /chat/sse`）零交集
- 本模块故障（如表不可用）不得影响百炼对话主流程（仅管理界面不可用）

## 2. 风险（R）

### R-01 AES 主密钥管理（低）
主密钥通过 env 注入，密钥泄露将导致所有 Provider 的 API Key 暴露。
**缓解**：密钥仅运维人员掌握；泄露时可通过管理界面批量更新 apiKey 轮换。

### R-02 管理员误操作（中）
删除 Provider 会级联删除其下所有 Model（软删除），误操作影响未来 Agent 的模型可用性。
**缓解**：软删除可恢复（DBA 直接改 `is_del`）；v1 前端删除按钮做二次确认（前端行为，后端不限制）。

### R-03 code 枚举扩展滞后（低）
新增 Provider 类型（如未来的 GEMINI、OLLAMA）需要改代码发版。
**缓解**：`CUSTOM` 类型兜底可配置任意 Provider；枚举扩展随版本迭代。

### R-04 无操作日志表（低）
v1 仅打印日志不做持久化操作记录，日志滚动后历史操作不可查。
**缓解**：审计字段记录最后修改人；v2 引入操作日志表（before/after 快照）。

### R-05 硬删除无法自助恢复（低）
软删除后无恢复接口，需 DBA 人工介入。
**缓解**：v1 接受（数据量小、操作频率低）；v2 视需求提供恢复接口。

## 3. Out of Scope 汇总

- 第三方模型的实际调用代码（Provider 适配器）—— 等待 Agent 开发
- 第三方模型的对话接口 —— v2+ 新增独立接口
- 模型推理参数管理（temperature、maxTokens 等）
- 用户自配模型（BYOK）—— 已明确从需求中移除
- 操作日志表（before/after 快照）
- 模型测试连通性
- 分页查询
- 与百炼模型的任何交互（`GET /chat/models` 标记 `@Deprecated` 迁移 v2，行为不变）
